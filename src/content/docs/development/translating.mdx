ekPanel should feel native in every language, not only in English. The panel's texts are plain
JSON files, so you do not need to know how to program to translate them. **Adding your language
is one of the most valuable contributions you can make.**

Today the panel is complete in **English** (the source language) and **বাংলা (Bangla)**.

## How translations work

- The web UI uses [i18next](https://www.i18next.com/). Every text the UI shows is a **key** in
  `web/src/i18n/locales/en.json`, such as `ftp.turn_on`, and the code asks for it with
  `t("ftp.turn_on")`. No user-facing text is written directly in the code.
- Each language is one file next to it with the same keys: `bn.json` for Bangla.
- **Notifications** (email, Telegram and so on) have their own, smaller files in
  `internal/notify/locales/`. They are sent in each recipient's language.
- **API errors** carry a stable `code`; the UI shows the text under `errors.<code>`.
- **Numbers, dates, sizes and units** ("3 minutes ago", "1.2 GB", Bengali digits in Bangla) are
  formatted by the browser for your language through `Intl`. Never write numbers or units into
  a translation by hand.
- **Right-to-left languages** (Arabic, Persian, Urdu, Hebrew…) mirror the layout automatically:
  the UI uses start and end instead of left and right.
- The panel picks the user's saved language, else the browser's, else English. Missing keys fall
  back to English.

A value looks like this. Keep everything inside `{{double braces}}` exactly as it is:

```json
"applying": "Applying your settings on {{server}}. This usually takes a few seconds.",
```

### Plurals

Keys ending in `_one` and `_other` are plural forms:

```json
"in_progress_one": "{{count, number}} task in progress",
"in_progress_other": "{{count, number}} tasks in progress"
```

Your language may need other forms (`_zero`, `_two`, `_few`, `_many`); see the
[CLDR plural rules](https://www.unicode.org/cldr/charts/latest/supplemental/language_plural_rules.html).
Give the forms your language uses. The checker accepts any set.

### Other things to know

- `<code>` tags in a value (for example in `setup.token_hint`) must stay around the same text.
- **Tone:** write the way a helpful person speaks: short, clear sentences, addressing the user
  politely (the formal "you", where your language has one). Prefer everyday words, but keep
  standard technical terms such as CPU, SSL, DNS and IP as your users know them.
- Error messages say what happened and what to do next.
- If something looks wrong in a right-to-left language, open an issue with a screenshot.

## Check a translation

```bash
cd web
npm run i18n:check
```

It prints how much of each file is translated, lists keys that are **missing** (the check fails,
in CI too) and keys that are **unused** (in your file but no longer in English). It also fails
when the code asks for a key that is not in `en.json`.

```text
ui bn.json: 100% translated
notifications bn.json: 100% translated
```

## Add a new language

<Steps>

1. Copy `web/src/i18n/locales/en.json` to `web/src/i18n/locales/<code>.json`, where `<code>` is
   the [ISO 639-1 code](https://en.wikipedia.org/wiki/List_of_ISO_639_language_codes) of your
   language (`es`, `ar`, `hi`, `id`, `tr`…).

2. Translate the values. Keep the keys and everything inside `{{double braces}}` unchanged.

3. Register the language in `web/src/i18n/index.ts`: add it to the `languages` list, with the
   language's own name for itself (`{ code: "es", name: "Español" }`), and to `resources`.

4. Add the code to `supportedLocales` in `internal/api/auth.go`, so the panel remembers it as a
   user's preference.

5. For notifications: copy `internal/notify/locales/en.json` to `<code>.json`, translate it,
   and add the code to the list of languages loaded in `internal/notify/notify.go`. (Until you
   do, notifications for users of that language fall back to English.)

6. Run `npm run i18n:check` in `web/`, then open a pull request.

</Steps>

<Aside type="tip" title="No Git? No problem">
You can also send a translated file by email (ekpanelbd@gmail.com), or report a wrong text with
the "Translation" issue template once the repository is public. A web translation platform
(Weblate or similar) is planned, so translators can work in the browser.
</Aside>

## Translate these docs

The docs site is in English and Bangla. Bangla pages live in `src/content/docs/bn/`, with the
**same file names and folders** as the English pages. A page that is not translated yet shows
the English page with a notice, so you can translate one page at a time.

<Steps>

1. Copy the English page to the same path under `bn/`, for example
   `src/content/docs/reference/faq.mdx` to `src/content/docs/bn/reference/faq.mdx`.

2. Translate the title, the description and the text. Keep commands, paths, code, and the
   panel's labels as they appear in the Bangla UI.

3. Leave links as they are (`/reference/glossary/`): on a Bangla page the site points them at
   the Bangla pages by itself. They work even for pages that are not translated yet, which show
   the English text with a notice.

4. Run `npm run dev`, switch the site's language to বাংলা, and read your page before you open a
   pull request.

</Steps>

### Bangla style

From [`WRITING.md`](https://github.com/ekPanel/ekPanel-docs/blob/HEAD/WRITING.md):

- Write natural Bangla, the way people in Bangladesh talk about computers.
- Technical words stay in English: website, server, database, backup, DNS, firewall, PHP. The
  sentence around them is Bangla.
- Keep commands, paths, labels in code and UI names exactly as they are.

### Another language for the docs

A new docs language needs an entry in `locales` in `astro.config.mjs`, a folder named after its
code under `src/content/docs/`, and translated sidebar group labels (the `translations` of each
group in the same file). Open an issue first, so we can plan it together. See
[Working on the docs](/development/docs/).
