ekPanel ধাপে ধাপে (phase) বানানো হচ্ছে। প্রতিটা phase শেষ হয় এমন কিছু দিয়ে যা আপনি একটা আসল server-এ
install করে ব্যবহার করতে পারেন। **Phase 0 থেকে 3 শেষ হয়েছে**, phase 4-এর প্রথম অংশটাও: release আর
update (4a)। এখান থেকেই 9 November 2026-এ প্রথম release, v0.1.0, বের হয়েছে। এরপর 4b-এর API অংশ (API token, OpenAPI
description আর `ekctl` command-line tool) শেষ হয়েছে, আর আসবে পরের release-এ, 4c-এর প্রথম অংশও তাই: একটা website বা app অন্য server-এ সরানো। এরপর আসছে 4c-এর
বাকিটা (শুধু database, অন্য server-এ backup, পুরো customer)।
প্রতিটা সিদ্ধান্ত আর test-সহ পুরো plan আছে main repository-র
[`PLAN.md`](https://github.com/ekPanel/ekpanel/blob/HEAD/PLAN.md)-এ।

<Aside type="caution" title="এখনো শুরুর দিকের software">
নিচে "শেষ" মানে একটা test server-এ (একটা local VM) বানানো আর test করা, production-এ ব্যবহার করা নয়।
প্রথম release, v0.1.0, বের হয়েছে: চালিয়ে দেখুন, test করুন, কিন্তু এখনই এতে গুরুত্বপূর্ণ কিছু host
করবেন না।
</Aside>

## শেষ হয়েছে

### Phase 0: ভিত্তি <Badge text="শেষ" variant="success" />

যে ভিত্তির ওপর বাকি সবকিছু বসে: panel আর agent, mutual TLS দিয়ে যুক্ত (agent বাইরের দিকে connect করে,
তাই NAT-এর পেছনের server কাজ করে); setup token দিয়ে sign in, argon2id password, two-factor
authentication আর rate limit; role; একটা append-only audit log; PostgreSQL-এ একটা task queue; ৩০ দিনের
history-সহ live server statistics; English আর বাংলায় web UI, ডান-থেকে-বাম ভাষার জন্য তৈরি; আর test VM
script-সহ `install.sh`।

## এরপর: phase 4, "আরও এগিয়ে"

৯ নভেম্বর ২০২৬ তারিখে ঠিক করা হয়েছে। অংশগুলো এই ক্রমে আসবে, প্রতিটা phase 3-এর মতো VM-এ test করা হবে।
Billing আসবে সবার শেষে, কারণ এটা API token (4b) আর reseller-এর (4e) ওপর নির্ভর করে।

### 4a. Release আর update <Badge text="শেষ" variant="success" />

VM-এ test key দিয়ে sign করা test release দিয়ে বানানো আর পরীক্ষা করা হয়েছে। **এখান থেকেই 9 November
2026-এ প্রথম release, [v0.1.0](https://github.com/ekPanel/ekpanel/releases/tag/v0.1.0), publish হয়েছে।**
এরপর আসছে 4b।

- CI-তে release build (Linux amd64 আর arm64), একটা tag থেকে হুবহু আবার বানানো যায় (reproducible),
  sign করা checksum তালিকা আর GitHub build attestation-সহ
- [এক লাইনের একটা installer](/start/install/), যা একটা release download করে আর এর signature check
  করে; `--agent` দিলে এটা agent আর web server-সহ [দ্বিতীয় একটা server set up করে](/start/add-server/)
- [Self-update](/start/upgrade/): panel নতুন release দেখায়, নিজেকে update করে (পুরোনো program রেখে
  দিয়ে, আর নতুনটা চালু না হলে সেটা ফিরিয়ে এনে), তারপর প্রতিটা agent update করে, একবারে একটা server
- Changelog থেকে release notes, আর [আপডেট](/guides/admin/updates/) page-এ প্রতিটা server-এর agent
  version
- এখনো বাকি: একটা web translation platform (Weblate বা এমন কিছু)

Release কীভাবে বানানো হয়: একজন owner `pub`-এ `vX.Y.Z` tag দেন। Release workflow amd64 আর arm64-এর জন্য
reproducible archive build করে, সুরক্ষিত `release` environment-এ রাখা key দিয়ে `SHA256SUMS` sign করে,
build attestation যোগ করে, আর release publish করে। `v1.2.3-rc.1`-এর মতো tag pre-release হয়, যা panel
কখনো update হিসেবে দেখায় না।

### 4b. API, CLI, Terraform <Badge text="আংশিক শেষ" variant="caution" />

`dev` branch-এ শেষ আর test করা হয়েছে; আসবে **পরের release-এ** (v0.1.0-এ নেই):

- প্রতি user-এর [API token](/guides/security/api-tokens/), scope আর মেয়াদ-সহ, একবার দেখানো, revoke করা যায়, আর
  audit log-এ এর নাম থাকে। Customer-দেরও আছে, কম scope নিয়ে। Token কখনো account-এর নিরাপত্তা বদলাতে, token
  manage করতে বা terminal খুলতে পারে না
- পুরো API-এর একটা [OpenAPI description](/reference/api/#the-openapi-description), `/api/v1/openapi.json`-এ (আর
  `docs/openapi.json`-এ), router থেকে বানানো আর CI-তে check করা, প্রতিটা operation-এর দরকারি scope-সহ; আর এই API
  docs
- [`ekctl`](/reference/cli/), Linux, macOS আর Windows-এর জন্য একটা command-line tool: server, website, database,
  app, DNS, backup আর task, `--json` output, আর যেকোনো endpoint-এর জন্য `ekctl api`
- একটা background task-এর খোঁজ রাখতে `GET /api/v1/tasks/{id}`

এখনো বাকি:

- একটা Terraform provider, phase 4-এর পরের দিকে, API stable হলে। OpenAPI description-এ request আর response schema
  আসবে এর সাথে
- ধীর কাজের খোঁজ রাখার একটাই উপায়: কাজ শুরু করে এমন প্রতিটা উত্তরে একটা `task_id` (আজ কোনো উত্তর task, কোনোটা
  state-সহ জিনিস, কোনোটা deployment)

### 4c. Server-এর মধ্যে সরানো <Badge text="আংশিক শেষ" variant="caution" />

`dev` branch-এ শেষ আর দুটো VM দিয়ে test করা হয়েছে; আসবে **পরের release-এ**:

- আপনার বেছে নেওয়া database সহ একটা [website অন্য ekPanel server-এ সরানো](/guides/websites/move/): owner আর ACL-সহ
  file, database, certificate, settings আর cron job। কিছু বদলানোর আগে নতুন server যাচাই করা হয়, panel যে DNS চালায় তা
  পেছনে যায়, আর আপনি না মোছা পর্যন্ত পুরোনো কপি চলতে থাকে। সরানো ব্যর্থ হলে website যেখানে ছিল সেখানেই থাকে
- একটা [app অন্য ekPanel server-এ সরানো](/guides/apps/move/): সংখ্যায় owner-সহ তার Docker volume, Git app-এর বর্তমান
  build (নতুন করে কিছু build হয় না), certificate, settings আর cron job। সরানোর সময় app বন্ধ থাকে; আপনি না মোছা পর্যন্ত
  পুরোনো কপি তার data সহ বন্ধ থাকে, আর সরানো ব্যর্থ হলে app যেখানে ছিল সেখানে আবার চালু হয়। Pull request preview-ওয়ালা
  app সরে না
- Copy যায় panel-এর সাথে agent-দের নিজস্ব connection দিয়ে, public SSH দিয়ে নয়

এখনো বাকি:

- শুধু একটা database সরানো
- অন্য server-এ backup restore করা; পুরো একজন customer সরানো

### 4d. Importer

- cPanel backup (account, file, database, mail, DNS, cron job, certificate)
- aaPanel-এর site আর database; অন্য host থেকে সাধারণ WordPress
- Coolify-এর application আর service
- কী import হয়েছে আর কী হয়নি, তার একটা report

### 4e. Reseller আর white-label

- নিজস্ব package আর customer-সহ reseller, administrator-এর দেওয়া সীমার মধ্যে
- White-label: নাম, logo, রং আর panel-এর domain
- বাছাই করা permission-সহ sub-user
- Passkey, আর active session-এর একটা তালিকা

### 4f. Security center

- প্রতি site-এ একটা WAF (OWASP Core Rule Set-সহ Coraza), প্রথমে শুধু detect করবে
- প্রতি site-এ আর panel-এর sign in-এর জন্য rate limiting; CrowdSec পড়ে না এমন service-এর জন্য blocking

### 4g. Billing integration

- WHMCS, Blesta আর Paymenter-এর জন্য provisioning module, panel-এ single sign-on-সহ
- এরপর built-in billing (Stripe, bKash, SSLCommerz), তখনো চাওয়া হলে

### আগের phase থেকে বাকি থাকা ছোট জিনিস

যেখানে মানায় সেখানে এগুলো সাথে নেওয়া হবে:

- একটা database browser, আর database import ও export
- আলাদা আলাদা file restore করা, আর একটা backup download করা
- Customer suspend করা, package-এ bandwidth-এর সীমা, ব্যর্থ cron job-এর alert
- Cloudflare বা built-in DNS দিয়ে wildcard certificate (DNS-01)
- একটা website, database বা app অন্য মালিকের কাছে সরানো
- Cloudflare API আর বাইরের mail delivery আসলভাবে চেষ্টা করে দেখা

## পরে: phase 5, game server

Container-এ Minecraft আর অন্য game server, console, file আর startup variable-সহ, Pterodactyl-এর মতো।
এগুলো একটা আলাদা module, আর hosting-এর অংশ release হয়ে ব্যবহার শুরু না হওয়া পর্যন্ত অপেক্ষা করবে।
