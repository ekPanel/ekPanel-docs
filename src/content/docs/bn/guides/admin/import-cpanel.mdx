একটা পুরো cPanel account তার full backup (`cpmove` file) থেকে আপনার কোনো server-এ নিয়ে আসতে পারেন: file-সহ তার website,
একই নাম, user আর password-সহ তার MySQL database, একই mailbox, password আর mail-সহ তার email, তার cron job, আর তার DNS
zone। কী আনবেন তা আপনি বেছে নেন, panel সেটা set up করে, আর শেষে একটা report বলে দেয় কী এসেছে আর কী আসেনি। Domain নতুন
server-এ point না করা পর্যন্ত visitor-দের জন্য কিছুই বদলায় না।

<Aside type="tip">
aaPanel বা অন্য যেকোনো host থেকে একটা website তার file-এর archive আর database dump হিসেবে আনতে হলে দেখুন
[ওয়েবসাইট আর্কাইভ ইমপোর্ট](/guides/admin/import-website/)। Coolify থেকে application আর service আনতে হলে দেখুন
[Coolify থেকে ইমপোর্ট](/guides/admin/import-coolify/)।
</Aside>

## শুরু করার আগে

- আপনি **admin**। Customer-রা এই পাতা দেখেন না; তবে আপনি কোনো customer-এর জন্য account ইমপোর্ট করতে পারেন।
- **Server connected**: এটা [panel-এ যোগ করা](/start/add-server/) আছে আর **সার্ভার** (Servers) পাতায় **অনলাইন** (Online)
  দেখায়। Website আর mailbox-গুলো এই server-এই থাকবে।
- **Server-এ যথেষ্ট খালি disk জায়গা আছে**: backup file, আর সাথে unpack করার পরে তার ভেতরের সবকিছু, মানে account-এর
  file, database আর mail। cPanel-এর home পাতায় এগুলোর size দেখায়। Server-এর পাতায় **ডিস্ক** (Disk) দেখুন; panel নিজে
  এটা check করে না।
- **আপনি server-এ file কপি করতে পারেন**, SSH দিয়ে (`scp` বা FileZilla-র মতো কোনো SFTP program), `root` হিসেবে বা `sudo`
  আছে এমন user হিসেবে।
- **Email** আনতে হলে server-এ [email চালু](/guides/dns/email/#turn-on-email-for-a-server) থাকতে হবে।
- **DNS zone** আনতে হলে [ekPanel-এর name server set up করা](/guides/dns/name-servers/#set-up-the-name-servers) থাকতে
  হবে। সেটা না থাকলেও বাকি সব আনতে পারবেন, আর zone আপনার DNS host-এই রেখে দিতে পারবেন।
- কোনো customer-এর জন্য ইমপোর্ট করলে, তাঁর [package](/guides/admin/customers/)-এ server-টা থাকতে হবে, আর যত website,
  database, cron job, mail domain আর mailbox আনছেন তার জায়গা থাকতে হবে।

## cPanel-এ backup বানান

আপনার লাগবে একটা **full account backup**, শুধু home folder বা শুধু database-এর backup না। এর যেকোনোটা দিয়ে পাবেন:

- **cPanel-এ**: **Backup** খুলে **Download a Full Account Backup**-এ click করুন। cPanel background-এ file-টা বানায়, আর
  তৈরি হলে জানিয়ে দেয়।
- **পুরোনো host-এর কাছ থেকে**: account-এর `cpmove` file-টা চেয়ে নিন।
- **WHM-এ**, যদি থাকে: **Transfer or Restore a cPanel Account**, বা পুরোনো server-এর command line-এ:

  ```bash
  sudo /scripts/pkgacct <cpanel user>
  ```

File-এর নাম হয় `cpmove-USER.tar.gz`-এর মতো (cPanel-এর **Backup** পাতা থেকে নিলে `backup-…_USER.tar.gz`)। Panel
`.tar.gz`, `.tgz` আর `.tar` file নেয়।

## Backup server-এ রাখুন

Server-এর agent শুধু একটা folder-এর backup পড়ে: `/srv/ekpanel/imports/` (agent নিজেই folder-টা বানায়, শুধু root পড়তে
পারে)। আপনার computer থেকে file-টা সেখানে কপি করুন:

```bash
scp cpmove-USER.tar.gz root@203.0.113.20:/srv/ekpanel/imports/
```

`203.0.113.20`-এর জায়গায় server-এর address আর `cpmove-USER.tar.gz`-এর জায়গায় file-এর নাম দিন। আপনি যে server বেছে নেন,
**ইমপোর্ট** (Import) পাতা তার জন্য `scp` লাইনটা দেখায়, সাথে একটা copy button।

<Aside type="caution">
Backup-এ account-এর সব file আর সব mail থাকে, সাথে তার database আর mailbox-গুলোর password hash। যতক্ষণ দরকার শুধু
ততক্ষণই রাখুন, আর [ইমপোর্টের পরে মুছে ফেলুন](#after-the-import)।
</Aside>

## Backup পড়ুন

<Steps>

1. Sidebar-এ **অ্যাডমিন** (Administration)-এর নিচে **ইমপোর্ট** (Import)-এ click করুন। `Ctrl+K` চেপে "ইমপোর্ট" লিখেও
   যেতে পারেন।

2. পাতায় তিনটা tab আছে। **cPanel ব্যাকআপ** (cPanel backup) রাখুন ("পুরো অ্যাকাউন্ট: ওয়েবসাইট, ডেটাবেস, ইমেইল, ক্রন জব,
   DNS"), পাতা খুললে এটাই খোলা থাকে। বাকি দুটো হলো **ওয়েবসাইট আর্কাইভ** (Website archive),
   [একটা archive থেকে একটা website](/guides/admin/import-website/) আনার জন্য, আর **Coolify**,
   [Coolify থেকে application আর service](/guides/admin/import-coolify/) আনার জন্য।

3. **সার্ভার** (Server)-এ সেই server বেছে নিন, যেখানে backup কপি করেছেন।

4. **ব্যাকআপ ফাইলের নাম** (Backup file name)-এ শুধু file-এর নাম লিখুন, folder ছাড়া: `cpmove-USER.tar.gz`,
   `/srv/ekpanel/imports/cpmove-USER.tar.gz` না। Field-এর নিচে "ফোল্ডারে এখন আছে: …" folder-এর সর্বোচ্চ পাঁচটা `.tar.gz`,
   `.tgz` আর `.tar` file-এর নাম দেখায়, নতুনটা আগে, আর লেখার সময় field-টা এগুলো suggest করে।

5. **ব্যাকআপ পড়ুন** (Read backup)-এ click করুন। "ব্যাকআপ পড়া হচ্ছে। বড় হলে কয়েক মিনিট লাগতে পারে।"

</Steps>

এরপর panel দেখায় **২. _user_ থেকে কী কী আনবেন বেছে নিন** (2. Choose what to import from _user_), সাথে cPanel-এর user
নাম আর তার home folder-এর size।

## কী আনবেন বেছে নিন

যা যা আনা যায়, শুরুতে সবগুলোতেই tick দেওয়া থাকে। যা চান না, তার tick তুলে দিন।

<Steps>

1. **ওয়েবসাইট** (Websites)-এর নিচে যে website-গুলো আনবেন, সেগুলোতে tick দিন। প্রতিটার পাশে লেখা থাকে **মূল ডোমেইন**
   (Main domain), **অ্যাডঅন ডোমেইন** (Addon domain) বা **সাবডোমেইন** (Subdomain), সাথে তার document root (যেমন
   `~/public_html`)। Parked domain আলাদা website না: সেগুলো মূল domain-এর নিচে "সাথে: …" হিসেবে দেখায়, আর তার extra domain
   হয়ে যায়।

2. প্রতিটা website-এর পাশে তার **PHP** version দেখে নিন। শুরুতে থাকে cPanel-এ website-টার যে version ছিল সেটা (সেই version
   এখানে না থাকলে "আগে ছিল 8.0" দেখায়)। ekPanel-এ আছে 8.5, 8.4, 8.3, 8.2, 8.1 আর 7.4; অন্য যেকোনো version 8.4 হয়ে যায়।
   কোনো customer-এর package হয়তো কয়েকটা version-ই allow করে; তখন package-এর প্রথম version-টা নেওয়া হয়।

3. **ডেটাবেস** (Databases)-এর নিচে যে MySQL database-গুলো আনবেন, সেগুলোতে tick দিন। প্রতিটার size আর user দেখায়।
   "নতুন পাসওয়ার্ড পাবে" (gets a new password) মানে password আনা যায়নি (দেখুন [Database](#databases))।

4. Account-এ cron job থাকলে, তাদের সংখ্যাসহ box-টা (যেমন **3টা ক্রন জব**) সবগুলো একসাথে আনে। এগুলো মূল website-এ যায়,
   তাই মূল website-এ tick থাকলেই শুধু এটায় tick দেওয়া যায়।

5. **ইমেইল** (Email)-এর নিচে যে mail domain-গুলো আনবেন, সেগুলোতে tick দিন। প্রতিটার পাশে একটা লাইন দেখায়, যেমন
   "2টা মেইলবক্স, 3টা ফরওয়ার্ডার, 34টা মেইল (5.2 MB)", কয়টা mailbox নতুন password পাবে ("1টা নতুন পাসওয়ার্ড পাবে"),
   আর mailbox-গুলোর নাম। একটা domain তার সব mailbox, forwarder আর mail নিয়েই আসে; আলাদা করে mailbox বাছা যায় না।
   Server-এ email চালু না থাকলে section-টা বলে "এই সার্ভারে ইমেইল চালু নেই। মেইলবক্স আনতে আগে ইমেইল চালু করুন
   (ইমেইল → সার্ভার)।", আর tick দেওয়া যায় না।

6. **DNS জোন** (DNS zones)-এর নিচে যে zone-গুলো আনবেন, সেগুলোতে tick দিন। প্রতিটার record-এর সংখ্যা দেখায়।
   "ekPanel-এর নেম সার্ভারে বানানো হবে। এখানকার ওয়েবসাইট আর ইমেইলের রেকর্ড ekPanel নিজে বানায়; cPanel-এর নিজের নামগুলো
   বাদ যায়; বাকি সব থাকে।" ekPanel-এর name server না থাকলে section-টা বলে zone আনা যাবে না, সেগুলো আপনার DNS host-এই
   রাখুন।

7. **কার জন্য** (For)-এ বেছে নিন যা আনছেন তার মালিক কে: **অ্যাডমিনদের (কোনো প্যাকেজ নয়)** (Administrators (no package))
   বা কোনো customer।

8. **এখনো ইমপোর্ট হয় না** (Not imported yet) box দেখালে (certificate আর `MAILTO`-এর মতো cron setting-এর জন্য) সেটা পড়ুন।
   তারপর **ইমপোর্ট করুন** (Import)-এ click করুন।

</Steps>

যে website-এর domain panel-এর অন্য কোনো website বা app আগে থেকেই ব্যবহার করছে, সেটায় **আগে থেকেই আছে** (Already here)
লেখা থাকে; যে database-এর নাম (বা user) server-এ আগে থেকে আছে, panel-এ যে mail domain-এর email আগে থেকেই আছে, আর panel-এ
যে zone আগে থেকেই আছে, সেগুলোতেও। এগুলোতে tick দেওয়া যায় না। **ইমপোর্ট করুন** button-এর পাশের লাইনটা আপনার বেছে নেওয়া
জিনিস গোনে, যেমন "3টা ওয়েবসাইট, 2টা ডেটাবেস, 2টা মেইল ডোমেইন, 2টা জোন"।

কোনো **customer**-এর জন্য ইমপোর্ট করলে panel আরও check করে:

- প্রতিটা mail domain customer-এর কোনো website (বা app)-এর domain, বা এখন যে website আনছেন তার domain;
- প্রতিটা zone-এর ভেতরে customer-এর কোনো website (বা app), বা এখন যে website আনছেন সেটা আছে;
- কোনো zone অন্য কোনো account-এর zone-এর ভেতরে পড়ে না, বা তাকে ঘিরে রাখে না;
- Package-এ mail domain আর mailbox-এর জায়গা আছে। Package-এ **মেইলবক্সের আকার** (Mailbox size) দেওয়া থাকলে প্রতিটা
  mailbox cPanel-এর quota-র বদলে সেই size পায়।

**ইমপোর্ট করুন**-এ click করলে panel সাথে সাথে website, database, mail domain, mailbox আর zone বানিয়ে ফেলে, তারপর একটা
task সেগুলো ভরে: "ওয়েবসাইট, ডেটাবেস আর ইমেইল তৈরি হচ্ছে, তারপর ফাইল, ডেটা আর মেইল কপি হবে। এই পেজ ছেড়ে গেলেও ইমপোর্ট চলতে থাকবে।"
চলার সময় প্রতিটা পাতার নিচের task box-এ এটা "cPanel অ্যাকাউন্ট _user_ ইমপোর্ট" নামে দেখায়।

## ইমপোর্টে কী হয়

একটা test VM-এ একটা ছোট account (MySQL database-সহ একটা PHP 8.2 website, একটা parked domain, একটা symbolic link আর
একটা cron job) পড়ে ইমপোর্ট করতে প্রায় 5 second লেগেছে, আর server-এ আগে PHP 8.2 install করতে হলে 51 second। Email (2টা
mailbox, 34টা mail) আর একটা DNS zone-সহ একই রকম account-এ লেগেছে প্রায় 15 second। বড় account-এ সময় লাগে তার file
unpack হতে আর mail কপি হতে যতক্ষণ লাগে।

### Website আর file

- আপনার বেছে নেওয়া প্রতিটা website একটা **PHP website** হয়, তার নিজের Linux account-সহ। Account-টা domain থেকে নতুন একটা
  নাম পায় (যেকোনো নতুন website-এর মতো), cPanel-এর user নাম না।
- Website-এর document root-এর file-গুলো যায় তার `public_html`-এ। কোনো addon domain-এর folder `public_html`-এর ভেতরে
  থাকলে সেটা শুধু নিজের folder পায়; বাকিটা পায় মূল website।
- cPanel home folder-এর অন্য file আর folder, যেগুলো কোনো document root-এর মধ্যে পড়ে না (script, private folder), সেগুলো
  যায় **মূল website-এর** home folder-এ, তার `public_html`-এর পাশে। মূল website না আনলে এগুলো বাদ পড়ে।
- চুপচাপ বাদ পড়ে: cPanel-এর নিজের folder (`mail`, `etc`, `.cpanel`, `tmp`, `logs`, `access-logs`, `ssl`, `.trash`,
  `.softaculous` আর এরকম আরও)। এগুলোর ভেতরের mail আলাদাভাবে ইমপোর্ট হয় (দেখুন [Email](#email))।
- আরও বাদ পড়ে, আর report-এ এগুলোর হিসাব থাকে: `public_ftp` আর `.htpasswds`-এর মতো অন্য folder, home folder-এর অন্য
  dotfile আর dotfolder (`.well-known` ছাড়া), website-এর বাইরে point করা symbolic link, আর pipe-এর মতো বিশেষ file।

### Database

- আপনার বেছে নেওয়া প্রতিটা database server-এ একটা MariaDB database হয়, **একই নাম**, **একই user** আর **একই password**-সহ:
  password hash-টা সাথে আসে। আপনার `wp-config.php` আর অন্য settings কিছু না বদলেই কাজ করে।
- ekPanel-এ প্রতিটা database-এর একটাই নিজস্ব user থাকে। cPanel-এ এক user অনেক database ব্যবহার করতে পারে: তখন প্রথম
  database user-টা রাখে, আর বাকি প্রতিটা database-এর নামে একটা নতুন user পায়, নতুন password-সহ। যে database-এর কোনো user
  ছিল না, সেটাও নতুন password-সহ একটা user পায়।
- নতুন password পাওয়া database-গুলো report-এ থাকে। প্রতিটার জন্য **ডেটাবেস** (Databases)-এ সেটা খুলুন, **নতুন পাসওয়ার্ড
  তৈরি করুন** (Create a new password)-এ click করুন, আর database-এর user আর নতুন password website-এর settings-এ বসান। দেখুন
  [Database](/guides/data/databases/#reset-a-password)।

### File-এর ভেতরের path

পুরোনো code আর settings-এ প্রায়ই cPanel-এর home folder-এর নাম থাকে, যেমন `/home/olduser/public_html/wp-content`। ইমপোর্ট
ছোট text file-গুলোতে `/home/<cPanel user>/…` বদলে নতুন জায়গা বসায়:

- কোনো website-এর document root-এর ভেতরের path হয়ে যায় সেই website-এর `public_html`;
- অন্য যেকোনো path হয়ে যায় মূল website-এর home folder।

শুধু 1 MB পর্যন্ত file বদলায়, আর শুধু code আর configuration: `.php`, `.inc`, `.ini`, `.env`, `.htaccess`, `.user.ini`,
`.json`, `.yml`, `.yaml`, `.xml`, `.conf`, `.cfg`, `.sh`, `.pl`, `.py`, `.cgi` আর `.txt`। কয়টা file বদলেছে, report তা
গোনে আর তালিকা দেয়।

**Database-এর ভেতরে** রাখা path (যেমন WordPress-এর `wp_options` table-এ, বা কোনো cache plugin-এর settings-এ) বদলায় না।
Website-এ এখনো পুরোনো folder-এর নাম থাকলে website-এর নিজের tool দিয়ে বদলান, যেমন WordPress-এ `wp search-replace`।

### Cron job

- Cron job-গুলো মূল website-এ যোগ হয় আর তার account হিসেবে চলে।
- Command-এ `/home/<cPanel user>/` বদলে মূল website-এর home folder হয়।
- cPanel যে PHP binary ব্যবহার করে (`/usr/local/bin/php`, `/opt/cpanel/ea-php82/root/usr/bin/php`, `ea-php82`, `php`),
  সেগুলো বদলে মূল website-এর PHP version হয়, যেমন `php8.2`।
- `MAILTO=…`-এর মতো settings লাইন ইমপোর্ট হয় না; report-এ সেগুলোর তালিকা থাকে। ekPanel এর বদলে প্রতিটা job-এর output তার
  পাতায় রাখে। দেখুন [Cron job](/guides/websites/cron/)।

### Email

আপনার বেছে নেওয়া প্রতিটা mail domain server-এর mail server-এ একটা [mail domain](/guides/dns/email/) হয়, সাথে:

- **Mailbox**: backup-এর `etc/<domain>/passwd`-এ যত mailbox আছে সব, একই নামে।
  - **Password**: cPanel SHA-512 crypt hash রাখে, আর ইমপোর্ট সেই hash-টাই রাখে, তাই mail program আর webmail **একই
    password**-এ চলে। পুরোনো ধরনের hash (যেমন MD5-crypt) রাখা যায় না: mailbox-টা একটা random password পায়, আর report-এ
    তার নাম থাকে। Mailbox-এর পাতায় **নতুন পাসওয়ার্ড** (New password) দিয়ে নতুন password বানিয়ে তার user-কে জানান।
  - **Size**: `etc/<domain>/quota` থেকে নেওয়া quota, বা customer-এর package-এ **মেইলবক্সের আকার** (Mailbox size)
    দেওয়া থাকলে সেটা।
  - যে mailbox-এর নাম ekPanel নেয় না, সেটা বাদ পড়ে, আর report-এ তা বলা থাকে।
- **Forwarder**, backup-এর `va/<domain>` থেকে:
  - যে address অন্য address-এ পাঠায়, সেটা একটা [forwarder](/guides/dns/email/#forwarders) হয়;
  - যে address একই সাথে mailbox আর forwarder, সেটা হয় [একটা copy forward করা](/guides/dns/email/#forwarding-and-auto-replies)
    mailbox, যে নিজেও একটা copy রাখে;
  - catch-all লাইন (`*: info@example.com`) ওই mailbox-কে domain-এর [catch-all](/guides/dns/email/#catch-all) বানায়।
    এখানে catch-all অবশ্যই domain-এর একটা mailbox হতে হয়: forwarder বা অন্য কোথাও পাঠানো catch-all set হয় না, report-এ লেখা থাকে;
  - যে লাইন mail কোনো program-এ (`|/home/user/script.php`) বা file-এ পাঠায়, বা ফিরিয়ে দেয় (`:fail:`, `:blackhole:`),
    সেগুলো ইমপোর্ট হয় না, report-এ তালিকা থাকে;
  - cPanel-এর default লাইন `*: <cPanel user>`, যা অজানা address-এর mail account-এর নিজের mailbox-এ পাঠায়, বাদ পড়ে:
    catch-all set না করলে ekPanel অজানা address-এর mail ফিরিয়ে দেয়।

### Mailbox-এর ভেতরের mail

- প্রতিটা mailbox-এর folder-এর (`mail/<domain>/<name>/`, cPanel-এর Maildir) সব mail mail server, Stalwart-এ কপি হয়:
  inbox আর সব folder, পড়া, উত্তর দেওয়া, flag দেওয়া আর draft চিহ্ন-সহ, আর প্রতিটা mail কখন এসেছিল সেই সময়-সহ।
- **Sent**, **Drafts**, **Trash**, **Junk** (বা **Spam**) আর **Archive** যায় mail server-এর নিজের ওই ধরনের folder-এ।
  অন্য folder একই নামে বানানো হয়, ভেতরের folder-ও (`Work.Projects` হয় **Work**-এর ভেতরে **Projects**), আর অন্য ভাষার
  নামও ঠিক থাকে।
- Mail program-এ মুছে ফেলা হিসেবে চিহ্ন দেওয়া (সরানোর অপেক্ষায় থাকা) mail বাদ পড়ে।
- 100 MB-এর বড় mail কপি হয় না। Report এগুলো "মেইল কপি করা যায়নি"-তে গোনে।
- Dovecot-এর **mdbox** format-এ রাখা mailbox (cPanel-এর নতুন একটা option) পড়া যায় না। Mailbox-টা খালি অবস্থায় বানানো
  হয়, আর report-এ তা বলা থাকে। ওই mail কোনো mail program বা `imapsync`-এর মতো tool দিয়ে সরান।

একটা test VM-এ 2টা mailbox-এর 34টা mail, 4টা folder-এ, কিছু বাংলায় লেখা, ঠিকঠাক এসেছে। পুরোনো cPanel password দিয়ে IMAP-এ
sign in করা গেছে, আর folder, না-পড়া আর flag দেওয়া চিহ্ন আগের মতোই ছিল।

### DNS zone

আপনার বেছে নেওয়া প্রতিটা zone (backup-এর `dnszones/<zone>.db` থেকে) ekPanel-এর name server-এ বানানো হয়, **কার জন্য**
(For)-এ যাকে বেছে নিয়েছেন তার নামে। Domain-এর registrar ekPanel-এর name server-এ point না করা পর্যন্ত কিছুই বদলায় না
(দেখুন [ইমপোর্টের পরে](#after-the-import))।

বাদ পড়ে, কারণ ekPanel এগুলো নিজে বানায় বা এগুলো cPanel-এর নিজের:

- `SOA` record আর domain-এর নিজের `NS` record;
- cPanel-এর নিজের নাম: `cpanel`, `whm`, `webmail`, `webdisk`, `cpcalendars`, `cpcontacts`, `autodiscover`, `autoconfig`,
  `_cpanel-dcv-test-record`, আর `_autodiscover`, `_caldav`, `_carddav`, `_imap`, `_pop3` আর `_submission` SRV record;
- panel-এর website আর app-এর `A`, `AAAA` আর `CNAME` record (এখন যেগুলো আনছেন সেগুলোসহ)। ekPanel এগুলো
  [নিজে বানায়](/guides/dns/name-servers/#records-made-automatically), server-এর দিকে point করে;
- Domain-এর email-ও আনলে, বা সেটা আগে থেকেই panel-এ থাকলে: তার `MX`, SPF, DKIM (`*._domainkey`), DMARC আর TLS reporting
  record। ekPanel নতুন করে বানায়, নতুন DKIM key-সহ।

বাকি সব থাকে: অন্য `A` record, অন্য service-এ যাওয়া `CNAME`, verification-এর `TXT` record, `CAA`, `SRV`, আর কোনো subdomain
অন্য name server-কে দেওয়ার `NS` record।

Report আরও জানায়:

- **যে record-গুলো এখনো পুরোনো cPanel server-এর দিকে**, যেমন `ftp.example.com`: "যে রেকর্ডগুলো এখনো পুরোনো সার্ভারের (…)
  দিকে: …"। এগুলো রাখা হয়; [zone editor](/guides/dns/name-servers/#the-zone-editor)-এ বদলান বা মুছুন।
- **যে `MX` record এখন email ছাড়াই এখানে point করে।** Zone আনলেন কিন্তু তার email আনলেন না, তাহলে তার `MX` record থেকে
  যায়। `MX` domain-এর নিজের দিকে point করলে (cPanel-এর default), mail এই server-এ আসবে, যেখানে ওই domain-এর email নেই।
  Email-ও আনুন, বা `MX` record বদলান।
- **যে record ekPanel রাখতে পারে না** (valid না), আর zone file-এর যে লাইনগুলো পড়া যায়নি, যেমন ekPanel-এ নেই এমন ধরনের
  record।

একটা test VM-এ ইমপোর্ট করা zone-এর `MX` ekPanel-এর mail host name-এর দিকে point করেছে, SPF, DKIM আর DMARC ছিল ekPanel-এর,
আর পুরোনো DKIM key চলে গেছে। একটা Google verification `TXT` record, একটা `CAA` record আর অন্য service-এ যাওয়া একটা `CNAME`
থেকে গেছে, cPanel-এর নামগুলো বাদ পড়েছে, আর `ftp` (পুরোনো server-এর দিকে point করা) রাখা হয়েছে আর report-এ তালিকায় এসেছে।

### Report

Task শেষ হলে পাতায় দেখায় **ইমপোর্ট শেষ** (Import finished), সাথে website, database, file-এর সংখ্যা আর size, cron job-এর
সংখ্যা, **ইমেইল** (Email; domain-গুলো, তারপর "_n_টা মেইলবক্স, _n_টা ফরওয়ার্ডার, _n_টা মেইল", আর কিছু কপি না হলে
"_n_টা মেইল কপি করা যায়নি") আর **DNS জোন** (DNS zones), তারপর:

- "_n_টা ফাইলে পুরোনো হোম ফোল্ডারের পাথ বদলানো হয়েছে", তালিকাসহ;
- "এই মেইলবক্সগুলোর পাসওয়ার্ড নতুন: …";
- নতুন password পাওয়া database-গুলো;
- **ইমপোর্ট হয়নি** (Not imported): যা বাদ পড়েছে সব, যেমন certificate, যে mail domain আর zone-এ tick দেননি, forwarding
  লাইন, পুরোনো server-এর দিকে point করা record, অন্য folder আর website-এর বাইরে point করা link।

## ইমপোর্টের পরে

<Steps>

1. **DNS বদলানোর আগে প্রতিটা website check করুন।** শুধু আপনার computer-এ domain-টা নতুন server-এ point করুন, তার `hosts`
   file-এ একটা লাইন যোগ করে (Linux আর macOS-এ `/etc/hosts`, Windows-এ `C:\Windows\System32\drivers\etc\hosts`):

   ```text
   203.0.113.20  example.com www.example.com
   ```

   Browser-এ website খুলে কয়েকটা পাতা, একটা login আর একটা form চালিয়ে দেখুন। Browser certificate নিয়ে সতর্ক করবে: DNS
   server-এ point করলে তবেই server আসল certificate পায়। কাজ শেষে লাইনটা মুছে দিন।

2. **Mailbox user-দের নতুন password জানান।** Report-এ যে mailbox-গুলোর নাম আছে, প্রতিটার পাতায় একটা নতুন password বানিয়ে
   তার user-কে দিন। বাকি সব mailbox-এর password আগের মতোই থাকে।

3. **Domain-গুলো server-এ point করুন।**
   - **Zone এনে থাকলে**: আগে report-এ পুরোনো server-এর দিকে point করা যে record-গুলোর তালিকা আছে, সেগুলো ঠিক করুন। তারপর
     প্রতিটা domain-এর registrar-এ name server বদলে ekPanel-এর গুলো দিন। দেখুন
     [Registrar-এ name server set করুন](/guides/dns/name-servers/#set-the-name-servers-at-the-registrar)।
   - **Zone না আনলে**: আপনার বর্তমান DNS host-এ প্রতিটা domain-এর, আর extra domain-গুলোর, `A` record (আর থাকলে `AAAA`)
     বদলে server-এর address দিন। Email সরিয়ে থাকলে `MX`, SPF, DKIM আর DMARC record-ও বদলে mail domain-এর পাতায় দেখানো
     record-গুলো দিন (দেখুন [DNS record](/guides/dns/email/#dns-records))।

   Domain সেখানে point করলে certificate নিজে থেকেই নেওয়া হয়।

4. **Mail program আবার connect করুন।** Domain-এর `MX` এখানে point করলে নতুন mail ইমপোর্ট করা mailbox-গুলোতে আসে। যে mail
   program server হিসেবে `mail.<domain>` ব্যবহার করত, তাকে এখন নতুন **মেইল হোস্ট নাম** (Mail host name) দিতে হবে: সেটা
   mail domain-এর পাতায় **মেইল অ্যাপ আর ওয়েবমেইল** (Mail apps and webmail)-এর নিচে দেখায় (দেখুন
   [Mail app settings](/guides/dns/email/#mail-app-settings))। User নাম আর password একই থাকে। Webmail পাবেন
   `https://<mail host name>/`-এ।

5. Server থেকে **backup মুছে ফেলুন**:

   ```bash
   sudo rm /srv/ekpanel/imports/cpmove-USER.tar.gz
   ```

</Steps>

<Aside type="tip" title="Backup-এর পরে আসা mail">
Backup বানানোর পরে, আর `MX` record এখানে point করার আগে, যে mail পুরোনো cPanel server-এ আসে, সেটা backup-এ থাকে না। DNS
বদলানো শেষ না হওয়া পর্যন্ত পুরোনো account রেখে দিন, তারপর ওই mail কোনো mail program বা `imapsync`-এর মতো tool দিয়ে সরান।
</Aside>

<Aside type="caution" title="এখানে .htaccess file কোনো কাজ করে না">
ekPanel-এর web server (Caddy) `.htaccess` file পড়ে না। WordPress, Laravel আর এরকম software-এর "সব request `index.php`-এ
পাঠাও" নিয়মটা আগে থেকেই আছে, তাই তাদের সুন্দর link-গুলো কাজ করতে থাকে। `.htaccess`-এর অন্য নিয়ম (redirect, বন্ধ করা
folder, password protection, `php_value` লাইন) কাজ করে না: সেগুলো [Redirect](/guides/websites/redirects/) আর website-এর
[PHP settings](/guides/websites/php/#php-settings-per-site)-এ নতুন করে বানান।
</Aside>

<Aside type="note">
Website-এর home folder (`/home/<account>`) website-এর নিজের account-এর জন্য read-only, কারণ SFTP account-টাকে এর ভেতরে
আটকে রাখে। যে script সরাসরি `/home/<cPanel user>/`-এ file লিখত, তাকে এর ভেতরের কোনো folder-এ লিখতে হবে, যেমন `tmp` বা
তার নিজের একটা folder। দেখুন [File](/guides/websites/files/)।
</Aside>

## API দিয়ে

`sites` scope-সহ admin-এর [API token](/guides/security/api-tokens/) দিয়ে ইমপোর্ট করা যায়। Customer-দের token দিয়ে যায় না।

| Endpoint | যা করে |
| --- | --- |
| `POST /api/v1/imports/inspect` | Backup পড়ে। Body: `{"server_id": "…", "file": "cpmove-USER.tar.gz"}`। ভেতরে কী আছে তা জানায় (`domains`, `databases`, `cron`, `mail`, `zones`, `old_ip` …), সাথে `taken_domains`, `taken_databases`, `php_versions`, `new_password_databases`, `mail_enabled`, `taken_mail`, `new_password_mailboxes`, `name_servers` আর `taken_zones`। Password hash কখনো পাঠানো হয় না। |
| `POST /api/v1/imports` | ইমপোর্ট করে। Body: `{"server_id", "file", "owner_id", "sites": ["example.com"], "php": {"example.com": "8.2"}, "databases": ["olduser_wp"], "cron": true, "mail": ["example.com"], "zones": ["example.com"]}`। `202` আর একটা [task](/reference/api/#tasks-following-slow-work) দিয়ে উত্তর দেয়; তার `result`-এ report থাকে। |

Admin-দের জন্য `owner_id` খালি রাখুন। [ekctl](/reference/cli/#any-endpoint-ekctl-api) দিয়ে:

```bash
ekctl api POST imports/inspect --data '{"server_id":"<server id>","file":"cpmove-USER.tar.gz"}'
ekctl api POST imports --data '{"server_id":"<server id>","file":"cpmove-USER.tar.gz","owner_id":"","sites":["example.com"],"databases":["olduser_wp"],"cron":true,"mail":["example.com"],"zones":["example.com"]}'
```

## সীমা আর যা এখনো নেই

cPanel account-এর এই অংশগুলো **ইমপোর্ট হয় না**:

- **SSL certificate**, ইচ্ছা করেই: domain server-এ point করলে নতুন certificate নেওয়া হয়।
- **Autoresponder, mail filter, mailing list আর cPanel-এর spam settings।** Mailbox-এর পাতায়
  [auto-reply](/guides/dns/email/#forwarding-and-auto-replies) set up করুন। ekPanel-এ এখনো mailing list নেই।
- **Account-এর নিজের default mailbox** (cPanel user-এর নিজের mail, কোনো domain-এর নিচে না)।
- **Dovecot-এর mdbox format-এ রাখা mail** (দেখুন [Mailbox-এর ভেতরের mail](#mail-in-the-mailboxes))।

এছাড়া:

- শুধু MySQL database ইমপোর্ট হয়, MariaDB database হিসেবে। Backup-এর PostgreSQL database বাদ পড়ে।
- সব website PHP website হয়। cPanel-এর Node.js, Python আর Ruby application file হিসেবে কপি হয়, কিন্তু চলে না; সেগুলো
  [app](/guides/apps/docker-apps/) হিসেবে set up করুন।
- FTP account আর cPanel-এর নিজের settings ইমপোর্ট হয় না। cPanel-এ বানানো redirect আর password দেওয়া folder থাকে
  `.htaccess` file-এ, যা ekPanel পড়ে না (দেখুন [ইমপোর্টের পরে](#after-the-import))।
- একটা backup একটা server-এ ইমপোর্ট হয়।
- cPanel-এর মতো করে বানানো ছোট backup দিয়ে test VM-এ চালিয়ে দেখা হয়েছে, এখনো অনেক আসল cPanel server-এর backup দিয়ে না,
  আর বাইরের আসল mail দিয়েও না।
- aaPanel আর অন্য host-এর website একটা একটা করে আসে [ওয়েবসাইট আর্কাইভ ইমপোর্ট](/guides/admin/import-website/) দিয়ে, আর
  Coolify-এর application আর service আসে [Coolify থেকে ইমপোর্ট](/guides/admin/import-coolify/) দিয়ে।

| "… জোনের জন্য এই গ্রাহকের ওই ডোমেইনে একটা ওয়েবসাইট লাগবে। ওয়েবসাইটটাও আনুন।" | ওই zone-এর ভেতরের কোনো website-এও tick দিন, বা zone admin-দের জন্য ইমপোর্ট করুন। |

| "এই সার্ভারে ইমেইল চালু নেই। আগে চালু করুন।" | Server-এ [email চালু করুন](/guides/dns/email/#turn-on-email-for-a-server), তারপর backup আবার পড়ুন। |
| "আগে ekPanel-এর name server চালু করুন (DNS পাতায়)।" | [Name server set up করুন](/guides/dns/name-servers/#set-up-the-name-servers), বা zone বাদ দিন। |
| "আপনার প্যাকেজে আর ওয়েবসাইট যোগ করা যাবে না।" (বা ডেটাবেস, ক্রন জব, মেইল ডোমেইন, মেইলবক্স) | Customer-এর package-এর limit বাড়ান, বা কম জিনিস আনুন। |
| "এই প্যাকেজ ওই সার্ভার ব্যবহার করতে পারে না।" | Customer-এর package-এ server-টা যোগ করুন, বা অন্য server বেছে নিন। |
| "ইমপোর্ট করার মতো অন্তত একটা কিছু বেছে নিন।" | অন্তত একটা website, database, mail domain বা zone-এ tick দিন। |

**ইমপোর্ট ব্যর্থ হয়েছে।** পাতায় **ইমপোর্ট ব্যর্থ হয়েছে** (The import failed) আর কারণ দেখায়। "এর জন্য প্যানেল যে ওয়েবসাইট,
ডেটাবেস, মেইল ডোমেইন আর DNS জোন বানিয়েছিল সেগুলো তালিকায় থেকে গেছে। আবার চেষ্টার আগে সেগুলো মুছে ফেলুন।" সেগুলো
ওয়েবসাইট, ডেটাবেস, **ইমেইল** (Email) আর **DNS**-এ মুছুন, তারপর backup আবার পড়ে ইমপোর্ট করুন।

**কোনো website database error দেখায়।** Report-এ নতুন password পাওয়া database আছে কিনা দেখুন, আর নতুন password-টা
website-এর settings-এ বসান। কোনো database ইমপোর্ট না হয়ে থাকলে সেটা আলাদা করে আবার ইমপোর্ট করুন: backup আবার পড়ে শুধু
ওই database-এ tick দিন।

**কোনো website ভুল file বা পুরোনো path দেখায়।** `/home/<cPanel user>/`-এর যে path ইমপোর্ট বদলায়নি সেগুলো খুঁজুন: 1 MB-এর
বড় file-এ, অন্য ধরনের file-এ, বা database-এ।

**কোনো mail program sign in করতে পারছে না।** Report-এ নতুন password পাওয়া mailbox আছে কিনা দেখুন। Program-টা user নাম
হিসেবে পুরো address আর server হিসেবে নতুন mail host name ব্যবহার করছে কিনা দেখুন (দেখুন
[Mail app settings](/guides/dns/email/#mail-app-settings))।

**কিছু mail কপি করা যায়নি।** এগুলো 100 MB-এর বড় mail, খালি file, বা mail server যে mail নেয়নি। দরকার হলে পুরোনো server
থেকে mail program দিয়ে সরান।
