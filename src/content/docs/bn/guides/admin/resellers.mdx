একজন **reseller** আপনার server-এ hosting বিক্রি করেন তাঁর নিজের customer-দের কাছে। আপনি তাঁকে limit দেন; সেই
limit-এর মধ্যে তিনি নিজের [package](/guides/admin/customers/#create-a-package) আর customer বানান, আর শুধু নিজের
customer-দেরই দেখেন। কোনো web designer, agency বা ছোট hosting ব্যবসা যদি নিজের নামে hosting বিক্রি করতে চান,
কিন্তু নিজে server চালাতে না চান, তখন এটা কাজে লাগে।

<Aside type="caution" title="v0.1.0-এর পরে নতুন">
Reseller আছে main repository-র `dev` branch-এ, আর আসবে **পরের release-এ**। v0.1.0-এর panel-এ এখনো **রিসেলার**
(Resellers) page নেই।
</Aside>

## শুরু করার আগে

- আপনি **admin** হিসেবে sign in করা আছেন। **রিসেলার** (Resellers) মেনুতে **অ্যাডমিন** (Administration)-এর
  নিচে, **গ্রাহক** আর **প্যাকেজ**-এর পাশে।
- আগে [Customer আর package](/guides/admin/customers/) পড়ে নিন: reseller-এর customer-রা সাধারণ customer-ই,
  প্রত্যেকের একটা করে package থাকে।
- ঠিক করে নিন reseller কোন কোন server, PHP version আর Docker image দিতে পারবেন।

## একজন reseller যোগ করুন

<Steps>

1. **রিসেলার** (Resellers) খুলে **রিসেলার যোগ করুন** (Add reseller)-এ click করুন।

2. একটা **নাম** (Name) আর **ইমেইল** (Email) দিন। এই email address দিয়েই তিনি sign in করবেন।

3. নিচে বলা তিন ভাগের limit পূরণ করুন: **সব গ্রাহক মিলিয়ে মোট**, **একটি প্যাকেজ সর্বোচ্চ কতটা দিতে পারে** আর
   **তাঁর প্যাকেজে কী কী দেওয়া যাবে**।

4. **রিসেলার বানান** (Create reseller)-এ click করুন।

5. Password copy করুন: "একটা পাসওয়ার্ড তৈরি হয়ে একবারই দেখানো হবে। পরে নতুন করে দিতে পারবেন।" "রিসেলারকে এই
   ঠিকানা আর পাসওয়ার্ড পাঠান। ঢোকার পর তিনি পাসওয়ার্ড বদলে টু-ফ্যাক্টর চালু করে নেবেন।"

</Steps>

Panel reseller-কে কোনো email পাঠায় না; password নিজে পাঠান, নিরাপদ কোনো উপায়ে।

### সব customer মিলিয়ে মোট

"রিসেলারের সব গ্রাহক মিলে কতটা রাখতে পারবেন।"

| Field | কী সীমিত করে | খালি বা 0 মানে |
| --- | --- | --- |
| **গ্রাহক** | Reseller কয়জন customer রাখতে পারবেন | 0 মানে একজনও না |
| **ওয়েবসাইট**, **ডাটাবেস**, **অ্যাপ**, **ক্রন জব** | তাঁর সব customer মিলিয়ে প্রতিটা কয়টা রাখতে পারবেন (0 থেকে 1,000,000) | 0 মানে একটাও না |
| **মেইল ডোমেইন**, **মেইলবক্স** | সব customer মিলিয়ে mail domain আর mailbox | 0 মানে একটাও না |
| **ডিস্ক (GB)** | সব customer মিলিয়ে যতটা disk space ব্যবহার করবেন | খালি: **সীমা নেই** |
| **মাসিক ব্যান্ডউইথ (GB)** | এক calendar মাসে (UTC) সব customer-এর website আর app মিলিয়ে যতটা পাঠায়, কমপক্ষে 1 GB। দেখুন [Bandwidth](#bandwidth) | খালি: **সীমা নেই** |
| **শেষ হয়ে গেলে তাঁর সব গ্রাহকের ওয়েবসাইট আর অ্যাপ বন্ধ করুন** | Bandwidth শেষ হলে প্রত্যেক customer-এর website আর app-এর address বন্ধ হবে কিনা | বন্ধ। শুধু bandwidth limit দিলেই টিক দেওয়া যায় |

### একটা package সর্বোচ্চ কতটা দিতে পারে

"খালি মানে যেকোনো। সীমা দিলে রিসেলারের প্রতিটি প্যাকেজে এর সমান বা কম সীমা থাকতেই হবে।"

| Field | কী সীমিত করে |
| --- | --- |
| **মেমরি (MB)** | Reseller-এর প্রতিটা package-এর memory limit, কমপক্ষে 64 MB |
| **CPU (কোর)** | প্রতিটা package-এর CPU limit, কমপক্ষে একটা core-এর 5% |
| **মেইলবক্সের আকার (GB)** | প্রতিটা package সর্বোচ্চ যত বড় mailbox দিতে পারে |

এগুলো প্রতি package-এর হিসাব, মোট নয়: **মেমরি (MB)** `1024` দেওয়া একজন reseller-এর দশজন customer থাকতে পারেন,
প্রত্যেকের 1024 MB করে।

### তাঁর package-এ কী কী দেওয়া যাবে

| Field | কী সীমিত করে | খালি মানে |
| --- | --- | --- |
| **PHP ভার্সন** | তাঁর package-এ কোন কোন PHP version রাখা যাবে | "কোনোটায় টিক না দিলে: সব PHP সংস্করণ।" |
| **সার্ভার** | তাঁর package কোন কোন server ব্যবহার করতে পারবে। "তাঁর গ্রাহকদের ওয়েবসাইট, ডেটাবেস আর অ্যাপ শুধু এগুলোতেই থাকবে।" | "কোনোটায় টিক না দিলে: সব সার্ভার।" |
| **অনুমোদিত Docker ইমেজ** | তাঁর package কোন কোন image দিতে পারবে। "প্রতি লাইনে একটি; / দিয়ে শেষ হলে তার নিচের সব চলবে।" শুধু **অ্যাপ** 0-এর বেশি হলে দেখায় | "খালি রাখলে: যেকোনো ইমেজ।" |
| **তাঁদের ওয়েবসাইটে SFTP**, **তাদের ওয়েবসাইটের জন্য FTP (এনক্রিপ্টেড)**, **Git অ্যাপ** | তাঁর package-এ এগুলো রাখা যাবে কিনা | বন্ধ |

### Reseller-এর limit বদলানো

Reseller-এর card-এ **রিসেলার বদলান** (Edit reseller)-এ click করে limit বদলান, তারপর **পরিবর্তন সেভ করুন**
(Save changes)-এ click করুন। Limit কমালে নতুন কিছু বানানো আটকে যায়। Customer-দের যা আগে থেকে আছে তা থেকে যায়,
আর নতুন limit-এর চেয়ে বড় package-গুলোও থাকে; তবে সেই package না কমিয়ে reseller সেটা আর save করতে পারবেন না।
নতুন bandwidth limit সাথে সাথে check হয় (দেখুন [Bandwidth](#bandwidth))।

কোনো সংখ্যা না নিলে: "সীমাগুলো দেখুন: সংখ্যা ০ বা তার বেশি, আর আকার যথেষ্ট বড় হতে হবে।"

## মোট কীভাবে গোনা হয়

"প্যাকেজে বেশি লেখা থাকতে পারে; গোনা হয় গ্রাহকদের আসলে যা আছে, আর কোনো মোট পূর্ণ হলে নতুন কিছু বানানো যায় না।"

Hosting ব্যবসায় যেমন হয়, একজন reseller নিজের যা আছে তার চেয়ে বেশি বিক্রি করতে পারেন। মোট 10টা website পাওয়া
একজন reseller 3টা website-এর বিশটা package বিক্রি করতে পারেন। Panel গোনে তাঁর সব customer-এর **আসলে যা আছে**:
website, database, app, cron job, email domain, mailbox আর disk space; আর কোনো মোট পূর্ণ হলে নতুনটা নেয় না, এমন
message দিয়ে: "রিসেলারের অ্যাকাউন্টে আর ওয়েবসাইট রাখা যাবে না।" প্রত্যেক customer-এর নিজের package-এর limit-ও
খাটে, তাই যে limit আগে পূর্ণ হয়, সেটাই আটকায়।

Reseller-এর customer-দের কিছু যোগ হয় এমন সবকিছুতে, যে-ই করুক, এই একই check চলে:

- reseller নিজে, বা customer নিজে;
- একজন admin, যিনি তাঁর কোনো customer-এর জন্য কিছু বানান (website, database বা app-এর form-এ **কার জন্য**
  (For)), বা তাঁদের কারও হয়ে [ঢোকেন](/guides/admin/customers/#sign-in-as-a-customer);
- তাঁর কোনো customer-এর জন্য [import](/guides/admin/import-cpanel/);
- [মালিক বদল](/guides/admin/customers/#change-the-owner), যা reseller-এর বাইরে থেকে তাঁর কোনো customer-কে কিছু দেয়।

**Disk space** মাপা হয় প্রতি 30 মিনিটে, [customer-দের](/guides/admin/customers/#how-disk-space-is-measured) মতোই।
Reseller-এর মোট শেষ হয়ে গেলে: "রিসেলারের অ্যাকাউন্টের ডিস্কের জায়গা শেষ।" তখন তাঁর সব customer-এর জন্য নতুন
website, database, app, cron job আর mail domain নেওয়া হয় না, file manager-এর যেসব কাজে data বাড়ে সেগুলোও না।
কিছুই মোছা হয় না, আর website চলতে থাকে।

**Server** ঠিক করে কোথায় কী বসবে: "রিসেলারের অ্যাকাউন্ট এই সার্ভার ব্যবহার করতে পারে না।"

Project-এর test VM-এ একজন reseller-এর মোট ছিল 2টা website। একজন customer একটা website বানিয়েছেন, আরেকজন
customer একটা, আর তৃতীয়টা নেওয়া হয়নি।

## Reseller কী দেখেন আর কী করেন

একজন reseller আপনার মতোই একই address-এ sign in করেন। তাঁর **ড্যাশবোর্ড**-এ লেখা থাকে "আপনার গ্রাহকদের ওয়েবসাইট,
ডেটাবেস আর অ্যাপ, আর আপনার রিসেলার অ্যাকাউন্টে কী কতটা আছে।" আর দেখায় **আপনার রিসেলার অ্যাকাউন্ট**: "আপনার
সব গ্রাহকের মোট, অ্যাডমিন আপনাকে যা দিয়েছেন তার তুলনায়।"

তিনি দেখেন:

- **ওয়েবসাইট**, **WordPress**, **ডাটাবেস**, **অ্যাপ**, **ইমেইল** আর **DNS**: তাঁর customer-দের যা আছে সব, আর
  কিছু না। বাকি সবকিছুর উত্তর হয় "not found", customer-দের বেলায় যেমন।
- মেনুতে **রিসেলার** (Reseller)-এর নিচে: **গ্রাহক** আর **প্যাকেজ**, শুধু তাঁর নিজের।
- নিজের account-এর **নিরাপত্তা**, **নোটিফিকেশন** আর **API টোকেন**।

তিনি পারেন:

- [নিজের package](#a-resellers-packages) বানাতে, আপনার দেওয়া limit-এর মধ্যে;
- নিজের customer যোগ, বদল আর মুছতে, তাঁদের **নতুন পাসওয়ার্ড** দিতে, **টু-ফ্যাক্টর রিসেট** করতে, **সাসপেন্ড** আর
  **সাসপেন্ড তুলুন** করতে, আর **তাঁর হয়ে ঢুকুন** দিয়ে তাঁদের হয়ে ঢুকতে;
- তাঁর কোনো customer-এর **জন্য** website, database, app, email domain, DNS zone আর cron job বানাতে;
- নিজের customer-দের মধ্যে জিনিসের [মালিক বদলাতে](/guides/admin/customers/#change-the-owner)।

Reseller-এর নিজের নামে কিছু থাকে না: তিনি যা বানান, সব তাঁর কোনো customer-এর হয়। Form-এ তিনি **কার জন্য** (For)-এ
customer বেছে নেন। এখনো কোনো customer না থাকলে form বলে "আগে একজন গ্রাহক যোগ করুন: রিসেলার হিসেবে আপনি যা
বানান, সব আপনার কোনো গ্রাহকের নামে থাকে।" API দিয়ে customer না দিলে আসে "কোন গ্রাহকের জন্য, সেটা বেছে নিন।"

### Reseller-এর নিজের website

নিজের website host করতে reseller নিজের জন্য একজন customer বানান, তাঁর কোনো একটা package দিয়ে, আর সেই customer-এর
জন্য website বানান। অন্য যেকোনো website-এর মতোই এটা তাঁর মোটে গোনা হয়।

### Reseller যা পারেন না

- **সার্ভার**, **ব্যাকআপ** আর **সার্ভার নিরাপত্তা**: শুধু বেছে নেওয়ার জন্য তাঁর ব্যবহারযোগ্য server-গুলোর নাম দেখেন। তিনি
  কিছু অন্য server-এ সরাতে পারেন না।
- **ইমপোর্ট**, **আপডেট** আর **অডিট লগ**।
- **রিসেলার**: তিনি নিজের reseller বানাতে পারেন না।
- Customer-এর **Cloudflare** account connect করা: "গ্রাহকের Cloudflare অ্যাকাউন্ট যুক্ত করতে গ্রাহকের হয়ে ঢুকুন।"
  Customer-এর পাশে **তাঁর হয়ে ঢুকুন** দিয়ে ঢুকে তাঁর হয়ে connect করুন।
- **মালিক বদলান…** দিয়ে admin-দের কিছু দেওয়া: শুধু নিজের কোনো customer-কে দিতে পারেন।
- Admin-এর করা suspend তুলে দেওয়া (দেখুন [Reseller-কে suspend করুন](#suspend-a-reseller))।

## Reseller-এর package

Package হয় admin-দের, নয়তো কোনো একজন reseller-এর। Reseller **প্যাকেজ**-এ আপনার মতোই নিজের package বানান (দেখুন
[একটা package তৈরি করুন](/guides/admin/customers/#create-a-package)), আর তাঁর customer-রা শুধু তাঁরই কোনো package
পেতে পারেন। Package-এর নাম প্রত্যেক reseller-এর মধ্যে আলাদা হতে হয়, তাই আপনার "Starter"-এর পাশে একজন reseller-এর
নিজের "Starter" package থাকতে পারে।

Reseller-এর package **reseller-এর যা আছে তার বেশি দিতে পারে না**:

- কোনো সংখ্যা reseller-এর মোটের বেশি নয় (10টা website-এর reseller-এর 20টা website-এর package নেওয়া হয় না);
- কোনো size "একটি প্যাকেজ সর্বোচ্চ কতটা দিতে পারে"-এর বেশি নয়, আর disk space বা bandwidth reseller-এর মোটের বেশি নয়;
- Reseller-এর যে size সীমিত, package-এ সেটা খালি রাখা যায় না, কারণ খালি মানে "সীমা নেই";
- শুধু reseller-এর PHP version, server আর image; আর SFTP, FTP বা Git অ্যাপ শুধু reseller-এর থাকলে।

দুটো ব্যতিক্রম: image শুধু app-সহ package-এর বেলায় খাটে, আর mailbox-এর size শুধু mailbox-সহ package-এর বেলায়।
যে reseller-এর image সীমিত, তিনি কোনো image না বেছেই 0 app-এর package বানাতে পারেন।

Package না আঁটলে panel field-টার নাম বলে: "এই প্যাকেজ আপনার রিসেলার অ্যাকাউন্টের সীমার চেয়ে বেশি দিচ্ছে: …। আপনার
সীমা ড্যাশবোর্ডে আছে; কোনো আকার খালি রাখলে মানে "সীমা নেই", যা সীমিত অ্যাকাউন্টে দেওয়া যায় না।"

Admin-রা সব package দেখেন। Package table-এ তখন একটা **কার** (Whose) column থাকে: **আপনার**, বা reseller-এর নাম।
আপনি কোনো reseller-এর package edit করলে, সেটাও সেই reseller-এর limit-এর সাথে মিলিয়ে check হয়।

## Reseller-কে suspend করুন

একজন reseller-কে suspend করলে তিনি **আর তাঁর সব customer** একসাথে থেমে যান, কিছু না মুছেই।

<Steps>

1. **রিসেলার**-এ reseller-এর card-এ **সাসপেন্ড** (Suspend)-এ click করুন।

2. কী হবে পড়ে নিন: "রিসেলার আর তাঁর সব গ্রাহক আর ঢুকতে পারবেন না, আর প্রত্যেক গ্রাহকের ওয়েবসাইট আর অ্যাপে
   "সাসপেন্ডেড" পেজ দেখাবে, ঠিক যেন প্রত্যেককে সাসপেন্ড করা হয়েছে।"

3. চাইলে একটা **কারণ** (Reason) লিখুন, সর্বোচ্চ 500 অক্ষর, admin-দের আর audit log-এর জন্য।

4. **সাসপেন্ড**-এ click করুন।

</Steps>

এরপর card-এ দেখায় "… থেকে সাসপেন্ডেড"। Reseller suspend থাকা অবস্থায়:

- **Reseller sign in করতে পারেন না**, তাঁর কোনো customer-ও না, password, passkey বা API token কোনোটা দিয়েই।
  তাঁদের খোলা session শেষ হয়ে যায়।
- **প্রত্যেক customer-কে suspend করা ধরা হয়**: তাঁদের website আর app-এর address "Website suspended" page (HTTP 503)
  দেখায়, app থামে, ইত্যাদি। এর পুরো মানে জানতে দেখুন [একজন customer-কে suspend করুন](/guides/admin/customers/#suspend-a-customer)।
- **কিছুই মোছা হয় না।**

সব আগের মতো করতে **সাসপেন্ড তুলুন** (Unsuspend)-এ click করুন। যে customer-দের **আলাদা করে** suspend করা হয়েছিল
(আপনি বা reseller), তাঁরা suspend-ই থাকেন।

একজন reseller নিজের customer-দের suspend করতে আর suspend তুলতে পারেন, কিন্তু admin-এর করা suspend তুলতে পারেন না:
"একজন অ্যাডমিন এই গ্রাহককে সাসপেন্ড করেছেন, তাই শুধু অ্যাডমিনই সেটা তুলতে পারবেন।"

Audit log আপনার নামে "রিসেলার সাসপেন্ড" (কারণ-সহ) আর "রিসেলারের সাসপেন্ড তোলা হয়েছে" লেখে।

Project-এর test VM-এ একজন reseller-কে suspend করলে তাঁর দুই customer-এর website "suspended" page (503)-এ চলে গেছে,
আর reseller ও দুই customer কারও sign-in নেওয়া হয়নি। Admin যে customer-কে suspend করেছিলেন, reseller-এর suspend তোলার
পরেও তিনি suspend-ই ছিলেন, আর reseller সেটা তুলতে পারেননি।

## Bandwidth

**মাসিক ব্যান্ডউইথ (GB)** দিলে reseller-এর bandwidth হলো **তাঁর সব customer-এর website আর app-এর traffic যোগ করে**,
UTC-র প্রতি calendar মাসে। এটা গোনা আর check হয় [customer-এর bandwidth](/guides/admin/customers/#how-bandwidth-is-counted)-এর
মতোই: প্রতি 15 মিনিটে traffic আনার সময়, আর সাথে সাথে, যখন আপনি reseller-এর limit বদলান বা কোনো customer-কে এক
reseller থেকে আরেকজনের কাছে সরান।

Reseller আর admin-রা একটা [notification](/guides/admin/notifications/) পান 90%-এ ("ব্যান্ডউইথ প্রায় শেষ") আর
100%-এ ("ব্যান্ডউইথ শেষ"), প্রতিটা মাসে একবার।

100%-এ:

- "শেষ হয়ে গেলে তাঁর সব গ্রাহকের ওয়েবসাইট আর অ্যাপ বন্ধ করুন" **ছাড়া**: কিছুই বন্ধ হয় না। এটা শুধু একটা সতর্কবার্তা।
- এটা **সহ**: notification হয় "ব্যান্ডউইথ শেষ, ওয়েবসাইট বন্ধ", আর পরের মাস পর্যন্ত প্রত্যেক customer-এর website আর
  app-এর address "Bandwidth used up" page (HTTP 503) দেখায়। Reseller-এর card-এ দেখায় "ব্যান্ডউইথ শেষ: ওয়েবসাইট বন্ধ",
  আর customer তালিকায় তাঁর প্রত্যেক customer-এর পাশে "রিসেলারের ব্যান্ডউইথ শেষ: ওয়েবসাইট বন্ধ"।

পরের মাসের প্রথম check-এ website-গুলো আবার চালু হয়, অথবা সাথে সাথে, যখন আপনি reseller-এর limit তাঁর ব্যবহারের চেয়ে
বেশি করেন বা বন্ধ রাখার টিক তুলে দেন। প্রত্যেক customer-এর নিজের package-এর limit-ও খাটে: reseller-এর bandwidth বাকি
থাকতেও একজন customer নিজের package-এর কারণে বন্ধ হতে পারেন।

Project-এর test VM-এ 1 GB-এর একজন reseller-এর দুই customer 600 MB আর 457 MB পাঠিয়েছেন, প্রত্যেকে নিজের 1 GB package-এর
নিচে। দুজনে মিলে 1.06 GB হতেই দুটো website bandwidth page-এ চলে গেছে আর reseller খবর পেয়েছেন। Reseller-কে 5 GB দেওয়ার
পর 2 সেকেন্ডের মধ্যে দুটোই ফিরে এসেছে।

## Reseller-এর notification

Customer-এর পাশাপাশি reseller-ও তাঁর customer-দের জিনিস নিয়ে alert পান: website, app, database বা email-এ সমস্যা,
ব্যর্থ deploy বা cron job, malware পাওয়া, কোনো customer-এর disk space বা bandwidth, ইত্যাদি। তিনি নিজের bandwidth-এর
alert-ও পান (ওপরে), আর নিজের account নিয়ে alert (নতুন address থেকে sign-in, recovery code ব্যবহার)। সবার মতো তিনিও
**নোটিফিকেশন**-এ নিজের channel সেট করেন। দেখুন [Notification](/guides/admin/notifications/)।

## Admin-দের জন্য: reseller-দের customer

Customer তালিকায় সব customer দেখায়, আর reseller-এর প্রত্যেক customer-এর নামের নিচে লেখা থাকে "…-এর মাধ্যমে"।

- **কিছু customer আলাদা করে দেখুন।** **দেখান** (Show)-এ বেছে নিন: **সব গ্রাহক**, **আপনার নিজের গ্রাহক**, বা একজন
  reseller-এর জন্য **…-এর গ্রাহক**। Reseller-এর card-এর **গ্রাহক** button সেই reseller-এর তালিকা খোলে।
- **একজন reseller-এর জন্য customer যোগ করুন।** **গ্রাহক যোগ করুন**-এ **রিসেলার** (Reseller) বেছে নিন। "রিসেলারের
  গ্রাহক সেই রিসেলারের কোনো প্যাকেজ পান, আর তাঁর সবকিছু রিসেলারের সীমার মধ্যে গোনা হয়।" তখন **প্যাকেজ** তালিকায় সেই
  reseller-এর package দেখায়।
- **একজন customer-কে অন্য reseller-এর কাছে, বা নিজের কাছে সরান।** Customer-এর **সম্পাদনা** (Edit)-এ click করুন, অন্য
  **রিসেলার**, বা **কেউ নয় (আপনার নিজের গ্রাহক)** বেছে নিন, আর তাঁর একটা package। কিছু বদলানোর আগে panel check করে
  নতুন reseller-এর আরেকজন customer-এর জায়গা আছে কিনা, আর customer-এর যা আছে সব (website, database, app, cron job,
  email, disk space আর server) আঁটে কিনা। Server-এ কিছুই সরে না। দুই reseller-এরই bandwidth আবার check হয়।
- **Reseller হিসেবে sign in করুন।** তিনি যেমন দেখেন তেমন দেখতে reseller-এর card-এ **তাঁর হয়ে ঢুকুন** (Sign in as)-এ
  click করুন, ঠিক [customer-এর](/guides/admin/customers/#sign-in-as-a-customer) মতো। Audit log-এ লেখা হয় "রিসেলারের হয়ে
  ঢোকা"। Reseller হিসেবে ঢুকে থাকা অবস্থায় তাঁর কোনো customer-এর হয়ে আবার ঢোকা যায় না ("আগে নিজের অ্যাকাউন্টে ফিরুন।"):
  ফিরে এসে customer-এর পাশে **তাঁর হয়ে ঢুকুন** ব্যবহার করুন।
- **নতুন পাসওয়ার্ড** আর **টু-ফ্যাক্টর রিসেট** reseller-এর বেলায়ও [customer-এর](/guides/admin/customers/#reset-a-password-or-two-factor-sign-in)
  মতোই কাজ করে।

Project-এর test VM-এ মালিক বদল একজন reseller-এর এক customer থেকে আরেকজনের কাছে একটা website সরিয়েছে, আর website
চলতেই ছিল।

### একজন reseller মুছে ফেলুন

যে reseller-এর এখনো customer আছেন, তাঁকে মোছা যায় না: "এই রিসেলারের এখনও গ্রাহক আছেন। আগে তাঁদের নিজের কাছে বা অন্য
রিসেলারের কাছে সরান, নয়তো মুছে ফেলুন।" প্রত্যেক customer-এর **সম্পাদনা** দিয়ে তাঁদের সরান, বা মুছে ফেলুন। তারপর reseller-এর
card-এ delete button-এ click করুন। "রিসেলারের অ্যাকাউন্ট আর প্যাকেজ মুছে যাবে।"

Project-এর test VM-এ customer থাকা অবস্থায় reseller মোছা নেওয়া হয়নি; customer-রা চলে যাওয়ার পর reseller আর তাঁর
package মুছে গেছে।

## API token আর API

Reseller-দের **API টোকেন**-এ নিজেদের [API token](/guides/security/api-tokens/) আছে, আটটা scope-সহ: **পড়া**,
**ওয়েবসাইট**, **ডেটাবেস**, **অ্যাপ**, **DNS**, **ইমেইল**, **গ্রাহক** আর **সেটিংস**। Reseller-এর token শুধু তাঁর
customer আর তাঁদের জিনিস দেখে, browser-এ reseller যেমন দেখেন। **গ্রাহক** scope দিয়ে এটা তাঁর customer আর package
সামলাতে আর তাঁর customer-দের মধ্যে মালিক বদলাতে পারে (`/customers`, `/packages` আর `/owner-changes`)।

Admin-রা reseller সামলান `/api/v1/resellers` (তালিকা, যোগ), `/api/v1/resellers/{id}` (দেখা, বদল, মোছা), আর তার নিচে
`/password`, `/2fa/reset`, `/impersonate`, `/suspend` (`{"reason": "…"}`-সহ) আর `/unsuspend`-এ `POST` দিয়ে। Token-এর
`customers` scope লাগে; two-factor sign-in reset আর কারও হয়ে ঢোকার জন্য browser session লাগে। দেখুন
[API reference](/reference/api/#administrators-and-resellers)।

## Limit আর যা এখনো নেই

- **White-label** (একজন reseller-এর জন্য panel-এর নাম, logo, রং আর domain) আর **sub-user** এখনো নেই। এগুলো
  [roadmap](/project/roadmap/)-এ phase 4e-এর পরের অংশ।
- Reseller নিজের reseller বানাতে পারেন না, আর নতুন reseller বা customer-দের sign-in তথ্যসহ email যায় না।
- "Website suspended" আর "Bandwidth used up" page ইংরেজিতে, আর এতে reseller-এর নাম থাকে না।
- Disk space মাপা হয় প্রতি 30 মিনিটে আর traffic আনা হয় প্রতি 15 মিনিটে, তাই নতুন কিছু আটকানো বা website বন্ধ হওয়ার
  আগে একজন reseller-এর customer-রা মোটের কিছুটা বেশি যেতে পারেন।
- মোট গোনে customer-দের যা আছে, তাই একজন reseller নিজের মোটের চেয়ে বেশি বিক্রি করতে পারেন। করলে তাঁর customer-রা
  package শেষ হওয়ার আগেই আটকে যেতে পারেন; সেটা সামলানো reseller-এর ব্যবসার ব্যাপার।
