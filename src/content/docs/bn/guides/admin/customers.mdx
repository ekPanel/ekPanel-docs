আপনি যদি অন্যদের website host করেন, তাহলে প্রত্যেককে একটা **customer** account দিন। একজন customer
একই panel-এ sign in করেন আর শুধু নিজের জিনিসগুলোই দেখেন, তাঁর **package**-এর limit-এর মধ্যে।
Package হলো একটা plan, যেমন "Starter" বা "Business": কয়টা website, database আর app, কতটা disk space,
আর তাঁর সব process মিলিয়ে কতটা memory আর CPU।

<Badge text="পরের release" variant="note" /> Customer কোনো [reseller](/guides/admin/resellers/)-এরও হতে পারেন:
reseller আপনার server-এ নিজের customer-দের কাছে hosting বিক্রি করেন, নিজের package দিয়ে, আপনার দেওয়া limit-এর মধ্যে।

## শুরু করার আগে

- আপনি **admin** হিসেবে sign in করা আছেন। Customer আর package মেনুতে **অ্যাডমিন** (Administration)-এর
  নিচে।
- কমপক্ষে একটা server connected আছে। দেখুন [Server যোগ করুন](/start/add-server/)।

## একটা package তৈরি করুন

<Steps>

1. **প্যাকেজ** (Packages) খুলে **প্যাকেজ যোগ করুন** (Add package)-এ click করুন।

2. একটা **নাম** (Name) দিন, যেমন `Starter`।

3. Limit-গুলো পূরণ করুন (নিচের table দেখুন)। যেমন: 3টা website, 3টা database, 1টা app, 10টা cron job,
   10 GB disk, 1024 MB memory, 1টা CPU core।

4. **প্যাকেজ তৈরি করুন** (Create package)-এ click করুন।

</Steps>

### Package limit

| Field | কী সীমিত করে | খালি বা 0 মানে |
| --- | --- | --- |
| **ওয়েবসাইট**, **ডাটাবেস**, **অ্যাপ**, **ক্রন জব** | Customer প্রতিটা কয়টা রাখতে পারবেন (0 থেকে 100,000)। WordPress staging-এর জন্য বানানো website-ও গোনা হয় | 0 মানে একটাও না। "অ্যাপ ০ মানে Docker অ্যাপ নয়।" |
| **মেইল ডোমেইন**, **মেইলবক্স** | Customer-এর সব domain মিলিয়ে mail domain আর mailbox | 0 মানে একটাও না |
| **মেইলবক্সের আকার (GB)** | একটা mailbox-এর সর্বোচ্চ size | খালি: কোনো limit নেই |
| **ডিস্ক (GB)** | Website file, app folder ও volume, database আর mail সব মিলিয়ে | খালি: সীমাহীন |
| **মেমরি (MB)** | Customer-এর **সব** PHP আর app process মিলিয়ে memory, কমপক্ষে 64 MB | খালি: কোনো limit নেই |
| **CPU (কোর)** | এগুলো সব মিলিয়ে CPU, যেমন `0.5` বা `2`, কমপক্ষে একটা core-এর 5% | খালি: কোনো limit নেই |
| <Badge text="পরের release" variant="note" /> **মাসিক ব্যান্ডউইথ (GB)** | Customer-এর website আর app এক calendar মাসে (UTC) যতটা data পাঠায়, কমপক্ষে 1 GB। দেখুন [Bandwidth কীভাবে গোনা হয়](#how-bandwidth-is-counted) | খালি: কোনো limit নেই |
| <Badge text="পরের release" variant="note" /> **শেষ হলে পরের মাস পর্যন্ত ওয়েবসাইট আর অ্যাপ বন্ধ রাখুন** | Bandwidth শেষ হলে website আর app-এর address উত্তর দেওয়া বন্ধ করবে কিনা। এটা ছাড়া customer আর admin-দের শুধু জানানো হয় | বন্ধ। Bandwidth limit না থাকলে সবসময় বন্ধ |
| **PHP ভার্সন** | তাঁদের website কোন কোন PHP version ব্যবহার করতে পারবে | "কিছু টিক না দিলে সব ভার্সন।" |
| **সার্ভার** | Customer কোথায় কিছু বানাতে পারবেন | "কিছু টিক না দিলে সব সার্ভার।" |
| **অনুমোদিত Docker ইমেজ** | তাঁদের app আর catalogue service কোন কোন image ব্যবহার করতে পারবে। প্রতি লাইনে একটা: `nginx`-এর মতো একটা নাম (যেকোনো tag), অথবা `/` দিয়ে শেষ হওয়া একটা prefix, যেমন `ghcr.io/acme/` | "খালি মানে যেকোনো ইমেজ।" |
| **তাঁদের ওয়েবসাইটে SFTP** | তাঁরা SFTP চালু করতে পারবেন কিনা | বন্ধ |
| **তাদের ওয়েবসাইটের জন্য FTP (এনক্রিপ্টেড)** | তাঁরা FTP চালু করতে পারবেন কিনা | বন্ধ |
| **Git অ্যাপ** | তাঁরা নিজেদের repository build আর deploy করতে পারবেন কিনা ([Git deploy](/guides/apps/git-deploys/)) | বন্ধ |

Customer-রা কখনো নিজের Compose file চালাতে পারেন না: "গ্রাহক Compose ফাইল ব্যবহার করতে পারেন না।" তাঁরা
একক image আর [catalogue](/guides/apps/catalog/)-এর যাচাই করা service চালাতে পারেন।

<Badge text="পরের release" variant="note" /> Reseller-রা নিজেদের package বানান। তখন package table-এ একটা **কার**
(Whose) column থাকে: **আপনার**, বা reseller-এর নাম। দেখুন [Reseller-এর package](/guides/admin/resellers/#a-resellers-packages)।

### Package বদলানো

একটা package edit করে save করুন। নতুন memory আর CPU limit সাথে সাথে customer-দের server-এ পৌঁছে যায়,
কিছু **restart না করেই**। কোনো সংখ্যা কমালে customer-দের যা আগে থেকে আছে তা থেকে যায়; তাঁরা শুধু
আর যোগ করতে পারেন না। নতুন bandwidth limit-ও সাথে সাথে check হয়: bandwidth-এর জন্য বন্ধ website-গুলো আবার
চালু হয়, যদি নতুন limit এই মাসের ব্যবহারের চেয়ে বেশি হয়, আর কম হলে বন্ধ হয়।

যে package-এ এখনো customer আছে, সেটা মোছা যায় না: "আগে এর গ্রাহকদের অন্য প্যাকেজে সরান।"

## একজন customer যোগ করুন

<Steps>

1. **গ্রাহক** (Customers) খুলে **গ্রাহক যোগ করুন** (Add customer)-এ click করুন।

2. তাঁর নাম আর email address দিন, আর একটা **প্যাকেজ** (Package) বেছে নিন।

3. **গ্রাহক তৈরি করুন** (Create customer)-এ click করুন।

4. Password copy করুন: "গ্রাহকের পাসওয়ার্ড, শুধু এই একবারই দেখানো হচ্ছে। নিরাপদ কোনো উপায়ে তাঁকে
   পাঠান।" Sign in করার পর তিনি **নিরাপত্তা** (Security)-তে এটা বদলাতে পারবেন।

</Steps>

Customer-এর panel-এর ভাষা শুরুতে হয় আপনার ভাষা, তাঁকে তৈরি করার মুহূর্তে আপনি যেটা ব্যবহার করছিলেন;
তিনি এটা বদলাতে পারেন।

<Badge text="পরের release" variant="note" /> আপনার [reseller](/guides/admin/resellers/) থাকলে form-এ **রিসেলার**
(Reseller)-ও থাকে: **কেউ নয় (আপনার নিজের গ্রাহক)**, বা একজন reseller। "রিসেলারের গ্রাহক সেই রিসেলারের কোনো প্যাকেজ
পান, আর তাঁর সবকিছু রিসেলারের সীমার মধ্যে গোনা হয়।" আগে থেকে থাকা একজন customer-কে কোনো reseller-এর কাছে, অন্য
reseller-এর কাছে, বা আবার নিজের কাছে সরাতে customer-এর **সম্পাদনা** (Edit)-এ click করে **রিসেলার** আর **প্যাকেজ**
বদলান; customer-এর যা আছে সব নিয়ে আগে নতুন reseller-এর limit check হয়।

Customer তালিকায় প্রত্যেক customer-এর package আর ব্যবহার দেখায়, যেমন website-এর "3-এর মধ্যে 2" আর
তাঁর disk space। পরের release থেকে এখানে **এই মাসের ব্যান্ডউইথ**-ও দেখায়, আর badge দেখায় সেই customer-দের পাশে,
যাঁরা [suspend করা](#suspend-a-customer) আছেন বা যাঁদের bandwidth শেষ হওয়ায় website বন্ধ ("ব্যান্ডউইথ শেষ: ওয়েবসাইট
বন্ধ")। Reseller-এর customer-এর পাশে reseller-এর নামসহ "…-এর মাধ্যমে" লেখা থাকে, আর **দেখান** (Show) দিয়ে **সব গ্রাহক**,
**আপনার নিজের গ্রাহক**, বা একজন reseller-এর customer দেখা যায়।

### Password বা two-factor sign-in reset করুন

কোনো customer password হারিয়ে ফেললে customer তালিকায় **নতুন পাসওয়ার্ড** (New password)-এ click করে নতুন
একটা বানান (একবার দেখানো হয়)। এতে তিনি সব জায়গা থেকে sign out হয়ে যান। এতে তাঁর two-factor sign-in বদলায় না।

<Badge text="পরের release" variant="note" /> কোনো customer two-factor sign-in চালু করে থাকলে আর তাঁর ফোন আর
[recovery code](/guides/security/accounts/#recovery-codes) দুটোই হারিয়ে ফেললে, আপনি তাঁর জন্য এটা বন্ধ করে দিতে
পারেন:

<Steps>

1. Customer তালিকায় customer-এর পাশে **টু-ফ্যাক্টর রিসেট** (Reset two-factor)-এ click করুন। বাটনটা শুধু সেই
   customer-দের পাশে দেখায়, যাঁদের two-factor sign-in চালু আছে।

2. নিশ্চিত করুন: "…-এর টু-ফ্যাক্টর সাইন-ইন বন্ধ করবেন? তিনি পাসওয়ার্ড দিয়ে সাইন-ইন করে আবার চালু করতে পারবেন।
   শুধু নিশ্চিত হলে করুন যে সত্যিই তিনিই চাইছেন।"

3. Customer-কে বলুন password দিয়ে sign in করে **নিরাপত্তা** (Security)-তে আবার two-factor sign-in চালু করতে। তখন
   তিনি দশটা নতুন recovery code পাবেন।

</Steps>

Reset করলে তাঁর recovery code-গুলোও মুছে যায়। এতে তাঁর passkey মোছে না, আর তিনি sign out-ও হন না। Audit log-এ
এটা আপনার নামে "গ্রাহকের টু-ফ্যাক্টর রিসেট" হিসেবে লেখা হয়। আপনার যদি মনে হয় customer-এর password অন্য কারও হাতে আছে,
তাহলে তাঁকে একটা **নতুন পাসওয়ার্ড**-ও দিন, এতে সব device থেকে sign out হয়ে যায়।

এই বাটন শুধু customer-দের জন্য। কোনো administrator ফোন হারালে recovery code, passkey, বা panel-এর server-এ
`ekpanel reset-2fa` ব্যবহার করেন: দেখুন [ফোন হারালে](/guides/security/accounts/#if-you-lose-your-phone)।

### Customer-এর জন্য কিছু তৈরি করা

Website, database বা app যোগ করার সময় **কার জন্য** (For)-এ customer-কে বেছে নিন। তখন সেটা তাঁর হয়ে যায়
আর তাঁর package-এ গোনা হয়, ঠিক যেন তিনি নিজেই বানিয়েছেন।

## Customer-রা কী দেখেন আর কী করেন

একজন customer আপনার মতোই একই address-এ sign in করেন। তিনি দেখেন:

- **ড্যাশবোর্ড** (Dashboard), যেখানে "আপনার প্যাকেজ: …", প্রতিটা limit-এর কতটা ব্যবহার হয়েছে, আর "এই মাসের
  ট্রাফিক: …"। পরের release থেকে এই লাইনটা হয় **এই মাসের ব্যান্ডউইথ** (Bandwidth this month), package-এ bandwidth
  limit থাকলে একটা meter-সহ (না থাকলে "… ব্যবহৃত, কোনো সীমা নেই"), আর কীভাবে গোনা হয় তার একটা note-সহ।
- **ওয়েবসাইট**, **ডাটাবেস**, **অ্যাপ**, **ইমেইল** আর **DNS**: শুধু যা তাঁর নিজের। Mail domain হতে
  হবে তাঁর নিজের website-এর domain; hosted DNS zone হতে হবে তাঁর নিজের website বা app-এর domain। তিনি
  নিজের Cloudflare account connect করতে পারেন।
- **নিরাপত্তা** (তাঁর password আর two-factor authentication; পরের release থেকে recovery code, passkey আর
  তাঁর sign in থাকা device-ও: দেখুন [Account-এর নিরাপত্তা](/guides/security/accounts/)) আর **নোটিফিকেশন**
  (তাঁর নিজের alert channel)।
- **API টোকেন** (API tokens, পরের release থেকে): script আর ekctl-এর জন্য তাঁর নিজের
  [token](/guides/security/api-tokens/), read, website, database, app, DNS আর email-এ সীমিত।

তিনি দেখেন **না**: অন্য customer-দের জিনিস, **ব্যাকআপ**, **সার্ভার** (শুধু বেছে নেওয়ার জন্য server-এর
নামের একটা তালিকা, তাঁর package অনুযায়ী সীমিত), **সার্ভার নিরাপত্তা**, **গ্রাহক**, **প্যাকেজ** বা
**অডিট লগ**। তিনি server terminal খুলতে পারেন না।

Customer-এর যা দেখার অনুমতি নেই, এমন যেকোনো কিছুর উত্তর হয় "not found", তাই ID বদলে বদলে কেউ অন্যের
website খুঁজে বের করতে পারে না। প্রতিটা route-এর জন্য মালিকানা check হয় এক জায়গায়; একটা automated test
অন্য customer হিসেবে 22টা route ঘুরে দেখে আর প্রতিটায় "not found" আশা করে।

## Memory আর CPU limit কীভাবে মানানো হয়

Limit-গুলো সত্যিকারের, শুধু panel-এর সংখ্যা নয়। প্রতিটা server-এ প্রত্যেক customer একটা **systemd
slice** পান (একটা Linux control group, cgroup v2), নাম `ekpanel-c<customer id>.slice`, package-এর
`MemoryMax` আর `CPUQuota`-সহ, আর সর্বোচ্চ 4,096টা process। Customer যা কিছু চালান সব এর ভেতরে যায়:

- **PHP**: তাঁদের website চলে তাঁদের নিজস্ব একটা PHP-FPM master-এর অধীনে, প্রতি PHP version-এ একটা,
  slice-এর ভেতরে।
- **Docker app আর catalogue service**: প্রতিটা container slice-টাকে তার cgroup parent হিসেবে পায়।
- **Git build**: build-ও slice-এর ভেতরে চলে।
- তাঁদের website আর app-এর **cron job**।

CPU দেওয়া হয় একটা core-এর শতাংশে: panel-এ `1` core মানে `CPUQuota=100%`, `0.5` মানে 50%।

Customer-এর process-গুলো মিলিয়ে package-এর চেয়ে বেশি memory চাইলে kernel **তাঁরই** একটা process থামিয়ে
দেয়, অন্য কারো নয়। Limit ছাড়িয়ে যাওয়া একটা PHP script শুধু নিজের worker-টাই হারায়; customer-এর অন্য
request চলতে থাকে। Project-এর test VM-এ, 256 MB-এর একটা package-এ, 400 MB চাওয়া একটা script একাই থেমে
গেছে, আর 50% CPU limit দুটো ব্যস্ত loop-কে 4 সেকেন্ডে 2 সেকেন্ড CPU দিয়েছে।

Admin-দের নিজের website আর app কোনো slice-এ নেই, আর তাঁদের কোনো package নেই।

## Disk space কীভাবে মাপা হয়

Disk space **panel মাপে**, filesystem quota দিয়ে নয়:

- প্রতি **30 মিনিটে** প্রতিটা server-এর agent website-এর home folder, আর app folder ও Docker volume যোগ
  করে হিসাব করে। প্রতিটা file একবারই গোনা হয়, link ধরে যাওয়া হয় না।
- **Database**-এর size জানানো হয় প্রতিবার server তার database-গুলো apply করার সময়।
- **Mailbox**-এর ব্যবহার আসে mail server থেকে।

Disk space শেষ হয়ে গেলে:

- নতুন website, database, app, cron job আর mail domain নেওয়া হয় না: "প্যাকেজের ডিস্কের জায়গা শেষ।"
- File manager-এর যেসব কাজে data বাড়ে (upload, নতুন file বা folder, unzip, zip), সেগুলো নেওয়া হয় না।
- কিছুই মোছা হয় না, আর website চলতে থাকে।

Customer আর admin-রা একটা [notification](/guides/admin/notifications/) পান 90%-এ ("ডিস্কের জায়গা প্রায়
শেষ") আর 100%-এ ("ডিস্কের জায়গা শেষ")।

<Aside type="caution">
যেহেতু জায়গা মাপা হয় প্রতি 30 মিনিটে, দুটো মাপের মাঝে একজন customer limit কিছুটা ছাড়িয়ে যেতে পারেন।
Disk limit দিয়ে **SFTP আর FTP upload থামে না**, আর চলমান website বা app লিখতে থাকতে পারে। শুধু panel-এর
নিজের কাজগুলোই নেওয়া হয় না।
</Aside>

## Bandwidth কীভাবে গোনা হয়

<Badge text="পরের release" variant="note" />

একটা package **মাসিক ব্যান্ডউইথ (GB)** দিয়ে সীমিত করতে পারে, একজন customer-এর website আর app প্রতি মাসে কতটা
data পাঠাতে পারবে।

- **কী গোনা হয়:** Customer-এর website আর app-এর address-এর জন্য web server যা পাঠায়, ঠিক যেমন
  [traffic chart](/guides/websites/logs-traffic/#traffic)-এর **Bandwidth**। Email, SFTP আর FTP, আর app যা download
  করে, তা গোনা হয় না।
- **মাস** মানে UTC-তে একটা calendar মাস। এটা আবার শুরু হয় 1 তারিখ 00:00 UTC-তে (বাংলাদেশে সকাল 6টায়)।
- **কখন check হয়:** Panel প্রতি 15 মিনিটে প্রতিটা server থেকে traffic আনে, আর ঠিক তারপরই প্রত্যেক customer-এর
  মাসের ব্যবহার তাঁর package-এর সাথে মেলায়। এছাড়া সাথে সাথে check হয় যখন আপনি একটা package বদলান, একজন
  customer-এর package বদলান, বা [মালিক বদলান](#change-the-owner) দিয়ে customer-দের মধ্যে website বা app সরান (পুরোনো আর নতুন দুই মালিকই check হন)।
- **Traffic কার:** এই মাসের traffic website বা app-এর সাথে যায়। একটা website অন্য customer-কে দিলে, এই মাসে সেটা
  যা পাঠিয়েছে তা নতুন মালিকের হিসাবে গোনা হয়।

Customer আর admin-রা একটা [notification](/guides/admin/notifications/) পান 90%-এ ("ব্যান্ডউইথ প্রায় শেষ") আর
100%-এ ("ব্যান্ডউইথ শেষ")। প্রতিটা মাসে একবার পাঠানো হয়।

100%-এ কী হয় তা package-এর ওপর নির্ভর করে:

- "শেষ হলে পরের মাস পর্যন্ত ওয়েবসাইট আর অ্যাপ বন্ধ রাখুন" **ছাড়া**: কিছুই বন্ধ হয় না। Customer limit পেরিয়ে
  যেতে পারেন; এটা শুধু একটা সতর্কবার্তা।
- এটা **সহ**: notification হয় "ব্যান্ডউইথ শেষ: ওয়েবসাইট বন্ধ", আর customer-এর website আর app-এর address প্রতিটা
  request-এর উত্তরে একটা ছোট page দেখায়, "Bandwidth used up", HTTP status 503-সহ। App চলতে থাকে, আর SFTP, FTP,
  cron job, database আর email কাজ করতে থাকে। Customer তালিকায় তাঁদের পাশে লেখা থাকে "ব্যান্ডউইথ শেষ: ওয়েবসাইট বন্ধ"।

পরের মাসের প্রথম check-এ (1 তারিখ 00:00 UTC-র 15 মিনিটের মধ্যে) website-গুলো নিজে থেকেই আবার চালু হয়, অথবা সাথে
সাথে, যখন আপনি customer-কে বড় package দেন, package-এর limit তাঁর ব্যবহারের চেয়ে বেশি করেন, বা বন্ধ রাখার
setting-টার টিক তুলে দেন।

<Aside type="caution">
Traffic প্রতি 15 মিনিটে আনা হয় বলে, website বন্ধ হওয়ার আগে একজন customer সর্বোচ্চ 15 মিনিটের traffic পরিমাণ limit
পেরিয়ে যেতে পারেন।
</Aside>

Project-এর test VM-এ, 1 GB-এর package-এ 1.1 GB পাঠানো একটা website "Bandwidth used up" page-এ চলে গেছে; package
2 GB করার পর 15 সেকেন্ডের মধ্যে সেটা ফিরে এসেছে।

## Customer হিসেবে sign in করুন

একজন customer ঠিক কী দেখেন তা দেখতে, বা তাঁর জন্য কিছু ঠিক করে দিতে:

<Steps>

1. Customer তালিকায় customer-এর পাশে **তাঁর হয়ে ঢুকুন** (Sign in as)-এ click করুন।

2. একটা banner দেখায় "আপনি … হিসেবে ঢুকেছেন। যা করবেন, সব আপনার নিজের নামেই লেখা থাকবে।"

3. Customer হিসেবে কাজ করুন। শেষ হলে **নিজের অ্যাকাউন্টে ফিরুন** (Back to my account)-এ click করুন।

</Steps>

- এটা সর্বোচ্চ **এক ঘণ্টা** থাকে।
- Audit log প্রতিটা কাজ **আপনার** নামে record করে, আর এটাও যে আপনি customer হিসেবে কাজ করেছেন।
- Customer-এর নিজের account security তাঁরই থাকে: তাঁর হয়ে sign in করা অবস্থায় আপনি তাঁর password
  বদলাতে, two-factor authentication চালু বা বন্ধ করতে, তাঁর recovery code, passkey বা sign in থাকা device
  দেখতে, তাঁর অন্য session sign out করাতে, তাঁর notification channel বদলাতে, বা তাঁর API token দেখতে বা
  বানাতে পারবেন না।
- পরের release থেকে customer তাঁর **সাইন ইন থাকা ডিভাইস** (Signed-in devices) তালিকায় আপনার এই sign-in
  **একজন অ্যাডমিন** (An administrator) চিহ্ন-সহ দেখেন, আর সেখান থেকে sign out করাতে পারেন।
- Customer হিসেবে sign in করা অবস্থায় terminal, app shell-সহ, পাওয়া যায় না।

## একজন customer-কে suspend করুন

<Badge text="পরের release" variant="note" />

Suspend করলে কিছু না মুছেই একজন customer-এর account থেমে যায়, যেমন bill না দিলে বা কোনো website-এর অপব্যবহার
হলে। Suspend তুলে দিলে সবকিছু আগের মতো হয়ে যায়।

<Steps>

1. Customer তালিকায় customer-এর পাশে **সাসপেন্ড** (Suspend)-এ click করুন।

2. চাইলে একটা **কারণ** (Reason) লিখুন, সর্বোচ্চ 500 অক্ষর: "অ্যাডমিন আর অডিট লগের জন্য; গ্রাহক এটা দেখেন না।"

3. **সাসপেন্ড**-এ click করুন।

</Steps>

এরপর customer-এর card-এ দেখায় "… থেকে সাসপেন্ডেড", আর কারণ দিয়ে থাকলে "কারণ: …"। শেষ করতে **সাসপেন্ড তুলুন**
(Unsuspend)-এ click করুন।

একজন customer suspend থাকা অবস্থায়:

- **তিনি sign in করতে পারেন না**, password, passkey বা API token কোনোটা দিয়েই। তিনি দেখেন "এই অ্যাকাউন্ট সাসপেন্ড
  করা আছে। আপনার হোস্টিং প্রোভাইডারের সাথে যোগাযোগ করুন।" (`account_suspended`)। তাঁর খোলা session-গুলো সাথে
  সাথে শেষ হয়ে যায়।
- **তাঁর website আর app-এর address** প্রতিটা request-এর উত্তরে ইংরেজিতে একটা ছোট page দেখায়, "Website suspended":
  "This website is suspended. If it is yours, please contact your hosting provider." Status হয় 503,
  `Retry-After: 3600`-সহ, যা search engine-কে বলে যে বন্ধ থাকাটা সাময়িক।
- **তাঁর app থামানো হয়।**
- **তাঁর cron job server-এ বিরতিতে যায়।** Panel-এ প্রতিটা job নিজের **চালু** (On) বা **বন্ধ রাখা** (Paused) setting
  রাখে, যা suspend তুলে দিলে আবার খাটে।
- তাঁর website-এর **SFTP আর FTP বন্ধ** থাকে।
- **তাঁর mailbox-এ sign in করা যায় না** (mail app আর webmail): mail server একটা random password পায়, যা কেউ জানে না।
  **Mail তবুও আসে** আর mailbox-এ অপেক্ষা করে।
- **কিছুই মোছা হয় না:** file, database আর mail থেকে যায়।

Suspend করা customer-এর জিনিস দেখতে বা ঠিক করতে আপনি তখনও [তাঁর হয়ে ঢুকুন](#sign-in-as-a-customer) ব্যবহার
করতে পারেন।

একজন [reseller](/guides/admin/resellers/)-ও নিজের customer-দের suspend করতে আর suspend তুলতে পারেন, কিন্তু admin-এর
করা suspend তুলতে পারেন না: "একজন অ্যাডমিন এই গ্রাহককে সাসপেন্ড করেছেন, তাই শুধু অ্যাডমিনই সেটা তুলতে পারবেন।"
একজন reseller-কে suspend করলে তাঁর সব customer-ও suspend হয়ে যান; দেখুন
[Reseller-কে suspend করুন](/guides/admin/resellers/#suspend-a-reseller)।

Audit log আপনার নামে "গ্রাহক সাসপেন্ড" (কারণ-সহ) আর "গ্রাহকের সাসপেন্ড তোলা হয়েছে" লেখে। API দিয়ে:
`POST /api/v1/customers/{id}/suspend`, `{"reason": "…"}`-সহ, আর `POST /api/v1/customers/{id}/unsuspend`
(token-এর `customers` scope লাগে)।

Project-এর test VM-এ একজন customer-কে suspend করলে তাঁর website-এ 503 page এসেছে, তাঁর app-এর container থেমেছে,
তাঁর cron job-এর timer বন্ধ হয়েছে আর তাঁর mailbox-এর IMAP sign-in নেওয়া হয়নি, অথচ mailbox-এ পাঠানো একটা message
ঠিকই পৌঁছেছে। Suspend তুলে দেওয়ার পর সব ফিরে এসেছে।

## মালিক বদলান

<Badge text="পরের release" variant="note" />

আপনি website, database, app, email domain আর DNS zone অন্য একজন customer-কে, বা admin-দের দিতে পারেন: যখন একজন
client তাঁর website অন্য কারও হাতে দেন, যখন আপনি একজন customer-এর জিনিস নিজে নিয়ে নেন, বা
[একজন customer মোছার](#delete-a-customer) আগে। Server-এ কিছুই সরে না।

<Steps>

1. Customer তালিকায় **মালিক বদলান…** (Change owner…)-এ click করুন: page-এর ওপরে, বা একজন customer-এর card-এ, তাঁকে
   দিয়ে শুরু করতে।

2. **যাঁর কাছ থেকে** (From) বেছে নিন: একজন customer, বা **অ্যাডমিনদের (কোনো প্যাকেজ নয়)**।

3. **যাঁকে দেবেন** (To) বেছে নিন: অন্য একজন customer (তাঁর package-সহ দেখায়), বা **অ্যাডমিনদের (কোনো প্যাকেজ নয়)**।

4. কী দেবেন টিক দিন: **ওয়েবসাইট**, **ডাটাবেস**, **অ্যাপ**, **ইমেইল ডোমেইন** আর **DNS জোন**-এর নিচে। DNS জোন মানে
   ekPanel-এর নিজের [name server](/guides/dns/name-servers/)-এর zone।

5. **…টি দিন**-এ click করুন। Panel উত্তর দেয়, যেমন "3টি এখন …-এর।"

</Steps>

কিছু বদলানোর আগে panel check করে:

- **নতুন মালিকের package**: তিনি কয়টা website, database, app, cron job (website আর app-গুলোর), email domain আর
  mailbox (email domain-গুলোর) রাখতে পারবেন, তাঁর disk space, আর কোন কোন server তিনি ব্যবহার করতে পারবেন। কোনো কিছু
  না আঁটলে কিছুই বদলায় না। Message-এ বলা থাকে কী আঁটছে না, যেমন "নতুন মালিকের প্যাকেজে এতগুলো ওয়েবসাইট রাখা
  যায় না।" Admin-দের দিলে কোনো limit নেই।
- **সরানো:** যে website, database বা app [অন্য server-এ](/guides/websites/move/) copy বা switch হচ্ছে, তার মালিক বদলানো
  যায় না: "… অন্য সার্ভারে সরানো হচ্ছে। সেটা শেষ হওয়া পর্যন্ত অপেক্ষা করুন।" Move switch হয়ে গেলে বদলানো যায়, পুরোনো
  কপি মোছার অপেক্ষায় থাকলেও।

নতুন মালিকের যা আগে থেকেই আছে তা বাদ যায়; সবকিছুই যদি তেমন হয়, panel বলে "এমন কিছু বেছে নিন যা নতুন মালিকের এখনো
নেই।"

যা বদলায়:

- **শুধু মালিক।** File, data, Linux account, address, password আর login যেমন আছে তেমনই থাকে। Website-এর PHP, app-এর
  container আর তাদের cron job এখন নতুন মালিকের [slice](#how-memory-and-cpu-limits-are-enforced)-এ চলে, নতুন মালিকের
  memory আর CPU limit-সহ (admin-দের দিলে কোনো limit নেই)।
- **Cron job, backup আর এই মাসের traffic website বা app-এর সাথে যায়।** একটা email domain তার mailbox আর forwarder
  সাথে নেয়। Database তার website-এর পেছনে যায় না: সেটাও টিক দিন।
- **DNS record zone-এর মালিককে অনুসরণ করে।** একজন customer-এর zone-এ ekPanel শুধু সেই customer-এর নিজের website, app
  আর email-এর record রাখে; admin-দের zone-এ যে কারও। তাই একটা website আর তার zone একসাথে দিন। এরপর name server
  update হয়।

Audit log "মালিক বদলেছে" লেখে, দেওয়া সবকিছুর নাম-সহ। API দিয়ে: `POST /api/v1/owner-changes`,
`{"to": "<customer ID, বা admin-দের জন্য খালি>", "sites": [...], "databases": [...], "apps": [...], "mail_domains": [...], "zones": [...]}`-সহ,
শুধু ID, একবারে সর্বোচ্চ 1,000টা (token-এর `customers` scope লাগে)।

একটা test VM-এ একটা website (তার cron job সহ), একটা app আর একটা email domain অন্য customer-কে দেওয়া হয়েছে, আর package-এর app limit তৃতীয় app ফিরিয়ে দিয়েছে।

## যা শুধু admin-রা পারেন

- Package আর customer তৈরি, বদল আর মুছে ফেলা, customer-দের password (আর পরের release থেকে তাঁদের two-factor
  sign-in) reset করা, আর তাঁদের হয়ে sign in করা।
- পরের release থেকে: customer suspend করা আর suspend তুলে দেওয়া, আর website, database, app, email domain ও DNS
  zone-এর মালিক বদলানো।
- পরের release থেকে: [reseller](/guides/admin/resellers/) যোগ করা আর সামলানো। একজন reseller-ও ওপরের দুটো কাজ করতে
  পারেন, তবে শুধু নিজের customer আর package-এর বেলায়।
- Server যোগ করা আর সরানো, তাদের metric আর service দেখা, আর একটা root
  [terminal](/guides/apps/terminal/) খোলা।
- [Backup](/guides/data/backups/), firewall, server security, email server আর built-in name server সেট
  করা।
- নিজের Compose file চালানো আর app-এর জন্য public port ব্যবহার করা।
- [Notification](/guides/admin/notifications/)-এর জন্য panel-এর SMTP server আর address সেট করা।
- Audit log পড়া।

প্রত্যেক admin-এর এই সব অধিকার আছে; ছোট কোনো admin role এখনো নেই।

## Customer অন্য server-এ সরান

একজন customer-এর এক server-এর সবকিছু (website, database আর app) অন্য server-এ সরাতে customer তালিকায় তাঁর পাশে
**সরান…** (Move…)-এ click করুন, তারপর **যেখান থেকে সরাবেন** (Move from) আর **যেখানে সরাবেন** (Move to) বেছে নিন। Panel
আগে সবকিছু check করে আর একটার পর একটা সরায়; পরে প্রতিটা পুরোনো কপি তার নিজের পাতা থেকে মুছে ফেলেন। দেখুন
[Customer সরান](/guides/admin/move-customer/)।

## একজন customer মুছে ফেলুন

যে customer-এর নামে এখনো কিছু আছে, তাঁকে মোছা যায় না: "তাঁর এখনো …টি ওয়েবসাইট, …টি ডেটাবেস আর …টি
অ্যাপ আছে। আগে সেগুলো মুছুন বা সরান।" আগে সেগুলো মুছুন, অথবা (পরের release থেকে) [মালিক বদলান](#change-the-owner)
দিয়ে অন্য customer বা admin-দের দিয়ে দিন। তারপর customer তালিকায় delete button-এ click করুন।

কিছু না হারিয়ে একজন customer-কে কিছুদিনের জন্য থামাতে চাইলে বরং তাঁকে [suspend করুন](#suspend-a-customer)।

## Limit আর যা এখনো নেই

- নতুন customer-দের sign-in তথ্যসহ **email**: এখনো নেই; password নিজে পাঠান।
- **Sub-user**: এখনো নেই। [Reseller](/guides/admin/resellers/), যাঁরা নিজের customer-দের কাছে hosting বিক্রি করেন,
  আর [branding (white-label)](/guides/admin/branding/) আসছে পরের release-এ।
- সত্যিকারের filesystem quota: এখনো নেই; disk space ওপরে যেভাবে বলা হয়েছে সেভাবে মাপা হয়।
- "Website suspended" আর "Bandwidth used up" page শুধু ইংরেজিতে, কারণ server visitor-এর ভাষা জানে না। এগুলো এখনো
  বদলানো যায় না।
- Bandwidth-এ শুধু web server যা পাঠায় তা গোনা হয়; website বন্ধ হওয়ার আগে একজন customer সর্বোচ্চ 15 মিনিটের traffic
  পরিমাণ limit পেরিয়ে যেতে পারেন।
- মালিক বদলানোয় ekPanel-এর নিজের name server-এর DNS zone আসে, Cloudflare zone নয় (customer-রা নিজের Cloudflare account
  connect করেন)।
