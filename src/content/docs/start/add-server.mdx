One panel can manage many servers. To add a server, you put the ekPanel agent on it and run
one command from the panel, and the server shows up with live statistics. You can then host
websites, databases and apps on it.

<Aside type="note" title="More manual than it will be">
There is no installer for an agent alone yet; it comes with the first release
([roadmap](/project/roadmap/), phase 4a). Today you copy the agent program yourself and, if
the server will host websites, prepare Caddy on it. This page shows every step.
</Aside>

## How enrolment works

1. In the panel you add a server by name. The panel answers with a **one-time token** and
   the **CA pin**, the fingerprint of the panel's private certificate authority.
2. On the new server, `ekpanel-agent enroll` connects to the panel on TCP port 7443. It
   checks the panel's certificate against the CA pin, so it cannot be tricked into talking to
   another machine.
3. The agent makes a private key that never leaves the server and sends the token with a
   certificate request. The panel checks the token and signs a client certificate valid for
   90 days. The token is then used up.
4. The agent saves its credential in `/etc/ekpanel/agent.json` (readable by root only).
5. `ekpanel-agent run` keeps a WebSocket connection open to the panel over **mutual TLS**:
   both sides prove who they are with certificates. The agent renews its certificate by
   itself 30 days before it expires, and reconnects after any interruption.

The connection is always opened **by the agent**. The new server needs no open incoming port
for it, so it can be behind NAT or a home router. Only the panel's server must accept
connections on port 7443.

The token works **once** and **expires after one hour**. The panel stores only a hash of it.

## Before you start

On the panel's server:

- TCP port **7443** must be reachable from the new server. The installer opens it in ufw if
  ufw is active; open it in your provider's cloud firewall too.

On the new server:

- Ubuntu 24.04+ or Debian 12+ on amd64 or arm64, with systemd, the same as for the
  [panel's server](/start/requirements/). The agent uses `apt` to install what features
  need, such as PHP, MariaDB or Docker.
- Root access. The agent runs as root, because it manages the server.
- Outgoing access to the panel on port 7443, and to the internet for packages.
- The `ekpanel-agent` program built for its CPU type. It is in the same
  [release archive](/start/install/#build-ekpanel) as the panel (`make release`).

## Prepare the server

<Steps>

1. Copy the agent to the server and install it:

   ```bash
   scp ekpanel-agent root@new-server:
   ```

   Then, on the new server:

   ```bash
   sudo install -m 0755 ekpanel-agent /usr/local/bin/ekpanel-agent
   sudo install -d -m 0755 /etc/ekpanel
   ```

   The second command creates the agent's folder readable for the web server, as the panel's
   installer does. If the agent created it, it would be closed to everyone but root, and
   Caddy could not read the website files the agent writes there.

2. If this server will host **websites or apps with a domain**, install Caddy and the `acl`
   package, and point Caddy at the folder where the agent writes one file per website. The
   panel's installer does this on the panel's server; on other servers you do it once by
   hand for now:

   ```bash
   sudo apt-get update
   sudo apt-get install -y curl gnupg acl
   curl -fsSL https://dl.cloudsmith.io/public/caddy/stable/gpg.key | sudo gpg --dearmor --yes -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
   curl -fsSL https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt | sudo tee /etc/apt/sources.list.d/caddy-stable.list
   sudo apt-get update
   sudo apt-get install -y caddy
   sudo install -d -m 0755 /etc/ekpanel/caddy/sites
   ```

   Then replace `/etc/caddy/Caddyfile` with:

   ```text
   # Websites are in /etc/ekpanel/caddy/sites.
   import /etc/ekpanel/caddy/sites/*.caddy
   ```

   and reload Caddy with `sudo systemctl reload caddy`. On Ubuntu, also install
   `software-properties-common`, which the agent uses to add the PHP package repository.

3. Create the agent's systemd service, so it starts at boot and restarts if it stops. This is
   the same unit the installer writes on the panel's server. Save it as
   `/etc/systemd/system/ekpanel-agent.service`:

   ```ini
   [Unit]
   Description=ekPanel agent
   After=network-online.target
   Wants=network-online.target

   [Service]
   # The agent manages this server (websites, services, files), so it runs as root.
   ExecStart=/usr/local/bin/ekpanel-agent run --config /etc/ekpanel/agent.json
   Restart=always
   RestartSec=3

   [Install]
   WantedBy=multi-user.target
   ```

   Then run `sudo systemctl daemon-reload`. Do not start it yet.

</Steps>

<Aside type="caution" title="Not tested as a recipe">
Step 2 copies what the panel's installer sets up, and the agent expects exactly that
(Caddy's configuration in `/etc/caddy/Caddyfile`, website files in
`/etc/ekpanel/caddy/sites`, and `setfacl` from the `acl` package). It has not been tested as
a separate recipe yet. If a website on the new server shows **Problem**, the message on the
website's page names what is missing.
</Aside>

## Connect it to the panel

<Steps>

1. In the panel, open **Servers** and click **Add server**.

2. Enter a **Server name** you will recognise, like "Singapore web 1", and click
   **Continue**.

3. The dialog **Connect** shows the command to run on the server. It looks like this:

   ```bash
   sudo ekpanel-agent enroll \
     --panel panel.example.com:7443 \
     --token <one-time token> \
     --ca-pin sha256:<fingerprint>
   ```

   The panel fills in its own host name, as you opened it in the browser, and the agent
   port. Copy the command with the copy button and run it on the new server. It answers
   `Enrolled as server …`.

4. Start the agent. The dialog suggests `sudo ekpanel-agent run`, which runs it in the
   foreground. Use the service from the step above instead, so it survives a reboot:

   ```bash
   sudo systemctl enable --now ekpanel-agent
   ```

5. Back in the panel, the dialog changes from **Waiting for the agent to connect…** to
   **Connected!** within a few seconds. Click **Done**.

</Steps>

The server now shows as **Online** on the **Servers** page, and you can pick it when you add
a website, database or app.

### The `enroll` command

```text
ekpanel-agent enroll --panel HOST[:7443] --token TOKEN --ca-pin sha256:... [--config PATH]
```

| Flag | Meaning |
| --- | --- |
| `--panel` | The panel's address for agents. Port 7443 is used when you leave it out. |
| `--token` | The one-time enrolment token from the panel. |
| `--ca-pin` | The fingerprint of the panel's agent CA, shown with the token. |
| `--config` | Where to save the credential. Default `/etc/ekpanel/agent.json`. |

`ekpanel-agent run [--config PATH]` starts the agent, and `ekpanel-agent version` prints its
version.

## How the panel's own server is connected

You do not add the panel's own server by hand. The installer runs `ekpanel add-server` on the
panel's server, which registers it under its host name and prints a token and CA pin, then
enrols the local agent at `127.0.0.1:7443`. It is the same enrolment as above, just
automatic.

## Behind NAT or a firewall

- **The new server** can be behind NAT, a home router or a strict firewall. It only needs to
  reach the panel on TCP port 7443. Its websites still need ports 80 and 443 reachable from
  the internet, of course.
- **The panel's server** must accept TCP 7443 from your servers. If the panel itself is
  behind NAT, forward port 7443 to it.
- For DNS records and FTP, ekPanel uses the first public address the server reports. A
  server behind NAT only knows its private address, so set its public address by hand on the
  server's page. See the [servers guide](/guides/admin/servers/).

<Aside type="caution" title="Panel domain behind Cloudflare's proxy">
Agents use mutual TLS with the panel's own certificate authority, which a proxy in between
would break. If your panel's domain is proxied through Cloudflare (orange cloud), use the
server's IP address or a name that is not proxied in `--panel`.
</Aside>

## When something goes wrong

- **The token expired or the command was lost.** Open the server on the **Servers** page and
  click **New connection command**. This makes a new token and revokes the server's current
  certificate, so an agent that was already connected is disconnected until you enrol it
  again.
- **"panel refused the request"**: the token was already used or has expired. Make a new
  connection command.
- **"contact panel" errors or a timeout**: the server cannot reach the panel on port 7443.
  Check the panel's firewall and your provider's cloud firewall.
- **The server shows Offline**: the agent is not running or cannot connect. On the server,
  check `sudo systemctl status ekpanel-agent` and `sudo journalctl -u ekpanel-agent`.
- **To remove a server**, open it and delete it. The panel forgets the server and its agent
  can no longer connect. Nothing on the server itself is deleted; stop and disable the agent
  service there yourself.
