One panel can manage many servers. To add a server, you give it a name in the panel and run
the one command the panel shows on the new server. The command installs the ekPanel agent and
the web server, connects the server to the panel, and the server shows up with live
statistics. You can then host websites, databases and apps on it.

<Aside type="note" title="Panels you built yourself">
The one command downloads your panel's own release from GitHub. If you built the panel from
source, use the steps in
[When the panel is not a published release](#when-the-panel-is-not-a-published-release).
</Aside>

## How enrolment works

1. In the panel you add a server by name. The panel answers with a **one-time token** and
   the **CA pin**, the fingerprint of the panel's private certificate authority.
2. On the new server, `ekpanel-agent enroll` (which the installer runs for you) connects to
   the panel on TCP port 7443. It checks the panel's certificate against the CA pin, so it
   cannot be tricked into talking to another machine.
3. The agent makes a private key that never leaves the server and sends the token with a
   certificate request. The panel checks the token and signs a client certificate valid for
   90 days. The token is then used up.
4. The agent saves its credential in `/etc/ekpanel/agent.json` (readable by root only).
5. `ekpanel-agent run` keeps a WebSocket connection open to the panel over **mutual TLS**:
   both sides prove who they are with certificates. The agent renews its certificate by
   itself 30 days before it expires, and reconnects after any interruption.

The connection is always opened **by the agent**. The new server needs no open incoming port
for it, so it can be behind NAT or a home router. Only the panel's server must accept
connections on port 7443.

The token works **once** and **expires after one hour**. The panel stores only a hash of it.

## Before you start

On the panel's server:

- TCP port **7443** must be reachable from the new server. The installer opens it in ufw if
  ufw is active; open it in your provider's cloud firewall too.

On the new server:

- Ubuntu 24.04+ or Debian 12+ on amd64 or arm64, with systemd, the same as for the
  [panel's server](/start/requirements/). Use a fresh server: ekPanel's web server needs
  ports 80 and 443. The agent uses `apt` to install what features need, such as PHP,
  MariaDB or Docker.
- Root access. The agent runs as root, because it manages the server.
- Outgoing access to the panel on port 7443, to `github.com` over HTTPS for the release,
  and to the internet for packages.

## Add the server

<Steps>

1. In the panel, open **Servers** and click **Add server**.

2. Enter a **Server name** you will recognise, like "Singapore web 1", and click
   **Continue**.

3. The dialog **Connect …** shows one command under **Install and connect**. It looks like
   this:

   ```bash
   curl -fsSL https://github.com/ekPanel/ekpanel/releases/download/v0.1.0/install.sh | sudo bash -s -- --agent \
     --panel panel.example.com:7443 \
     --token <one-time token> \
     --ca-pin sha256:<fingerprint>
   ```

   The version in the address is your panel's own version, so the new server gets the same
   agent version as the panel. The panel fills in its own host name, as you opened it in the
   browser, and the agent port.

4. Copy the command with the copy button and run it on the new server as root. It takes a
   few minutes, most of it package downloads, and ends with "This server is connected to the
   panel."

5. Back in the panel, the dialog changes from **Waiting for the agent to connect…** to
   **Connected!** within a few seconds. Click **Done**.

</Steps>

The server now shows as **Online** on the **Servers** page, and you can pick it when you add
a website, database or app.

### What the command does

It runs the same installer as for the panel, with `--agent`. On the new server it:

- installs `ca-certificates`, `curl`, `gnupg`, `openssl`, `acl` and, on Ubuntu,
  `software-properties-common`, and Caddy from Caddy's official package repository if it is
  not installed yet. It does not install PostgreSQL or the panel;
- downloads the agent from the panel's release and checks it, exactly as the
  [panel's install](/start/install/#how-the-download-is-checked) does;
- installs it as `/usr/local/bin/ekpanel-agent`, creates `/etc/ekpanel` and
  `/etc/ekpanel/caddy/sites` (readable by the web server), and writes the
  `ekpanel-agent` systemd service;
- enrols the agent with the token and CA pin, then enables and starts the service, so the
  agent also runs after a reboot;
- writes `/etc/caddy/Caddyfile`, which imports `/etc/ekpanel/caddy/sites/*.caddy` (one file
  per website, written by the agent). If the server already has a Caddyfile of its own, the
  installer only adds the `import` line to it. Then it checks the configuration and reloads
  Caddy;
- opens ports 80 and 443 in ufw, if ufw is active.

Running the same command again on a server that is already connected installs the agent
again and keeps its connection; it does not enrol a second time. The installer refuses to run
with `--agent` on the panel's own server, whose agent the panel's installer already set up.

## When the panel is not a published release

The one command needs your panel's version to exist as a release on GitHub. That is not the
case when you [built the panel yourself](/start/install/#install-from-your-own-build):

- A panel built **from source** (with `make build`, or a version that is not a release) shows
  two commands instead, with the note "This panel is built from source, so there is no
  release to install from. Copy the ekpanel-agent binary to /usr/local/bin on the new server
  first."
- A panel built with `make release VERSION=…` shows the one command, but its download does
  not exist on GitHub and fails with a 404 error.

In both cases, run the installer from your own build, with the values from the dialog:

<Steps>

1. Copy the archive you installed the panel from (the same version) to the new server, and
   unpack it there:

   ```bash
   scp dist/ekpanel-v0.0.1-linux-amd64.tar.gz root@new-server:
   ```

   ```bash
   tar -xzf ekpanel-v0.0.1-linux-amd64.tar.gz
   cd ekpanel-v0.0.1-linux-amd64
   ```

   With a `make build` build, copy `bin/ekpanel-agent` and `deploy/install.sh` into one
   folder on the new server instead.

2. In the panel, click **Add server**, enter a name and click **Continue**. Take the
   `--panel`, `--token` and `--ca-pin` values from the command the dialog shows.

3. Run the installer with `--agent` and those values:

   ```bash
   sudo ./install.sh --agent --local-dir . \
     --panel panel.example.com:7443 \
     --token <one-time token> \
     --ca-pin sha256:<fingerprint>
   ```

   It does everything listed in [What the command does](#what-the-command-does), except
   the download.

4. Wait for **Connected!** in the dialog, and click **Done**.

</Steps>

The two commands of a from-source panel (`sudo ekpanel-agent enroll …`, then
`sudo ekpanel-agent run`) also work once `ekpanel-agent` is in `/usr/local/bin`. They only
connect the agent: they set up no web server, no `acl` package and no systemd service, and
`run` keeps the agent in the foreground of your SSH session. Use them for a quick test, not
for a server that hosts websites.

### The `enroll` command

```text
ekpanel-agent enroll --panel HOST[:7443] --token TOKEN --ca-pin sha256:... [--config PATH]
```

| Flag | Meaning |
| --- | --- |
| `--panel` | The panel's address for agents. Port 7443 is used when you leave it out. |
| `--token` | The one-time enrolment token from the panel. |
| `--ca-pin` | The fingerprint of the panel's agent CA, shown with the token. |
| `--config` | Where to save the credential. Default `/etc/ekpanel/agent.json`. |

`ekpanel-agent run [--config PATH]` starts the agent, and `ekpanel-agent version` prints its
version.

## How the panel's own server is connected

You do not add the panel's own server by hand. The installer runs `ekpanel add-server` on the
panel's server, which registers it under its host name and prints a token and CA pin, then
enrols the local agent at `127.0.0.1:7443`. It is the same enrolment as above, just
automatic.

## Behind NAT or a firewall

- **The new server** can be behind NAT, a home router or a strict firewall. It only needs to
  reach the panel on TCP port 7443. Its websites still need ports 80 and 443 reachable from
  the internet, of course.
- **The panel's server** must accept TCP 7443 from your servers. If the panel itself is
  behind NAT, forward port 7443 to it.
- For DNS records and FTP, ekPanel uses the first public address the server reports. A
  server behind NAT only knows its private address, so set its public address by hand on the
  server's page. See the [servers guide](/guides/admin/servers/).

<Aside type="caution" title="Panel domain behind Cloudflare's proxy">
Agents use mutual TLS with the panel's own certificate authority, which a proxy in between
would break. If your panel's domain is proxied through Cloudflare (orange cloud), use the
server's IP address or a name that is not proxied in `--panel`.
</Aside>

## When something goes wrong

- **The token expired or the command was lost.** Open the server on the **Servers** page and
  click **New connection command**. This makes a new token and revokes the server's current
  certificate, so an agent that was already connected is disconnected until you enrol it
  again. On a server where the agent is already installed, the one-line command does not enrol
  again (it keeps the existing credential), so run the `enroll` part yourself with the values
  from the new command, then restart the agent:

  ```bash
  sudo ekpanel-agent enroll --panel panel.example.com:7443 --token <one-time token> --ca-pin sha256:<fingerprint>
  sudo systemctl restart ekpanel-agent
  ```
- **"the panel did not accept this server. The token works once and expires; create a new
  one in the panel."** (from the installer), or **"panel refused the request"** (from
  `enroll`): the token was already used or has expired. Make a new connection command.
- **"contact panel" errors or a timeout**: the server cannot reach the panel on port 7443.
  Check the panel's firewall and your provider's cloud firewall.
- **`curl: (22) The requested URL returned error: 404`**: your panel's version is not a
  published release. See
  [When the panel is not a published release](#when-the-panel-is-not-a-published-release).
- **"this server runs the panel; its agent is already set up."**: you ran the `--agent`
  command on the panel's own server. It needs nothing more.
- **The server shows Offline**: the agent is not running or cannot connect. On the server,
  check `sudo systemctl status ekpanel-agent` and `sudo journalctl -u ekpanel-agent`.
- **To remove a server**, open it and delete it. The panel forgets the server and its agent
  can no longer connect. Nothing on the server itself is deleted; stop and disable the agent
  service there yourself (`sudo systemctl disable --now ekpanel-agent`).
