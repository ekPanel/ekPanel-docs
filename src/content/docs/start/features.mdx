This page lists what works in ekPanel today. Each group links to its guide. Everything here
was tested on an Ubuntu 24.04 test server; where something has not been tried against a real
outside service, the list says so.

<Aside type="note">
Everything on this page is in v0.1.0, the first release, except
[API and command line](#api-and-command-line), moving websites, apps, databases and
customers to another server, and rebuilding a website from a backup (under
[Many servers](#many-servers)), which come with the next release. You can
[install it](/start/install/) with one command.
</Aside>

## Websites

[Websites guide](/guides/websites/websites/) · [PHP](/guides/websites/php/) · [Redirects](/guides/websites/redirects/)

- Static sites and PHP sites. PHP 7.4, 8.1, 8.2, 8.3, 8.4 and 8.5 side by side; a version is
  installed the first time a site needs it.
- Switching a site's PHP version with no downtime.
- Free automatic HTTPS from Let's Encrypt, a self-signed certificate for testing, or your own
  certificate (checked against its key and domain, with a notice two weeks before it
  expires).
- Extra domains per site, `www.` offered by default, and domain names in any script.
- Each site runs as its own Linux account with its own PHP-FPM pool, so one site cannot
  read another's files.
- Redirects (301, 302, 307, 308) of exact paths or prefixes, and extra domains that redirect
  to the main one.
- Hotlink protection for chosen file types, with sites that may still embed them.
- PHP settings per site (memory limit, upload size, execution time, time zone and more) and
  17 optional PHP extensions per server (redis, imagick, apcu, xdebug and others).
- A document root setting for apps that serve a `public/` or `web/` folder.
- Files such as `.env` and `.git` are never served.

## WordPress

[WordPress guide](/guides/websites/wordpress/)

- One-click WordPress, with its own MariaDB database, in 14 languages. The admin password is
  shown once and not stored.
- Every WordPress site in one list, including ones installed by hand.
- Core, plugin and theme updates that are undone automatically if the site shows an error
  afterwards; automatic updates by rules per site.
- Maintenance mode, plugins on and off, and a warning when debug mode is on.
- Hardening: no code editing from the dashboard, `xmlrpc.php` and PHP in uploads blocked,
  file permissions fixed.
- A staging copy at `staging.<domain>` that you can push to the live site or refresh from it.

## PHP apps

[PHP apps guide](/guides/websites/php-apps/)

- One-click Joomla, Drupal, Moodle and Laravel, each with its own database and (except
  Laravel) a one-time admin password. Moodle gets its cron job by itself.

## Files, SFTP and FTP

[Files guide](/guides/websites/files/)

- A file manager in the browser: upload (drag and drop), download, a code editor, new files
  and folders, rename, permissions, zip and unzip, and a trash you can restore from.
- SFTP per site, with a password or SSH keys, locked into the site's folder and without a
  shell.
- FTP for tools that need it: encrypted only (FTPS), a login per site, locked into its
  folder. The firewall opens the FTP ports only while a site uses FTP.

## Cron jobs

[Cron guide](/guides/websites/cron/)

- Jobs for websites (run as the site's account) and for apps (run inside a container).
- Presets or any cron expression, in your time zone, with the next five runs shown.
- Time limits, last result and output, "run now" and pause.

## Logs and traffic

[Logs and traffic guide](/guides/websites/logs-traffic/)

- The request log of each website and app, with a status filter, search and a live mode.
- The PHP error log of each website.
- Traffic charts (requests, data, status codes, most requested paths) for 24 hours, 7 and
  30 days. History is kept for 90 days.

## Docker apps

[Docker apps guide](/guides/apps/docker-apps/)

- Run any Docker image or Compose file, with a domain and free HTTPS, variables, kept
  folders, and memory and CPU limits.
- Container logs, restart, stop and start, and "update image" in one click.
- App ports stay on `127.0.0.1`, so Docker cannot open holes in the firewall. Compose files
  that publish public ports are refused unless you allow it.
- Deleting an app keeps its data unless you choose to delete that too.
- <Badge text="next release" variant="note" /> [Move an app](/guides/apps/move/) with its data
  to another server.

## App catalogue

[Catalogue guide](/guides/apps/catalog/)

- 14 one-click services: Uptime Kuma, Grafana, n8n, Gitea, IT Tools, Vaultwarden, Umami,
  Ghost, listmonk, Nextcloud, Memos, Excalidraw, ntfy and Redis.
- Passwords and keys are generated for each install. Customers can install them too, within
  their package.

## Git deploys and previews

[Git deploys guide](/guides/apps/git-deploys/)

- Build a repository on your server on every push, with webhooks from GitHub, GitLab,
  Gitea, Forgejo and Gogs.
- Builds use the repository's Dockerfile, or Railpack when there is none (it detects the
  language and framework).
- The build log streams live. Releases happen without downtime; a release that does not
  start is removed and the old one keeps serving.
- Roll back to any of the last five builds in one click.
- A preview app for each pull request at its own address, removed when the pull request
  closes. Pull requests from forks are never previewed.
- Private repositories use a deploy key that ekPanel makes.

## Web terminal

[Terminal guide](/guides/apps/terminal/)

- A root shell on any server for administrators, and a shell inside an app's container for
  the app's owner, in the browser.
- Opening one asks for your password (and two-factor code) again. Sessions end after 30
  minutes without typing and after 8 hours. Opening and closing are in the audit log.

## Databases

[Databases guide](/guides/data/databases/)

- MariaDB and PostgreSQL, installed on first use, with one account per database that can
  reach only that database.
- Passwords are shown once and never stored; the panel keeps only the database's own hash.
- Connection details, size and password reset.
- <Badge text="next release" variant="note" /> [Move a database](/guides/data/move-database/) on
  its own to another server.

## Backups

[Backups guide](/guides/data/backups/)

- Encrypted, deduplicated backups (with restic) of every website and database on a server,
  to the server itself or to S3-compatible storage (Amazon S3, Backblaze B2, Cloudflare R2,
  Wasabi, MinIO and others).
- Hourly, daily, weekly or manual, with daily, weekly and monthly copies kept.
- The encryption key is a recovery key shown once. The panel never stores it.
- Restore a website into a new folder or over the current files, and a database in place.
- <Badge text="next release" variant="note" /> When a server is lost,
  [rebuild its websites on another server](/guides/websites/rebuild/) from their S3 backups.

## Cloudflare DNS

[Cloudflare guide](/guides/dns/cloudflare/)

- Connect a Cloudflare account with an API token; every website, app and preview under a
  domain then gets its DNS records, kept in sync.
- A zone editor, the SSL mode check, cache purge, and visitors' real addresses in your logs.
- Customers can connect their own account for their own domains.

<Aside type="caution">
Cloudflare support was tested against a fake Cloudflare API, not yet against the real one.
</Aside>

## Your own name servers with DNSSEC

[Name servers guide](/guides/dns/name-servers/)

- Turn ekPanel servers into name servers (PowerDNS): one primary and any number of
  secondaries, kept in sync by zone transfer.
- A zone editor for A, AAAA, CNAME, MX, TXT, SRV, CAA and NS records, and templates for new
  zones.
- Records for websites, apps and email made automatically.
- DNSSEC per zone, with the DS record to give your registrar, and guidance for glue records.

## Email

[Email guide](/guides/dns/email/)

- A mail server (Stalwart) set up by the panel, with webmail (Roundcube).
- Mailboxes with sizes, forwarders, catch-all, forwarding and auto-replies.
- MX, SPF, DKIM and DMARC records published to Cloudflare or your own name servers, or shown
  to copy elsewhere.
- A delivery check for reverse DNS, outgoing port 25 and blocklists.

<Aside type="caution">
Email was tested inside a test server only. Delivery to and from real outside mail servers
has not been tried yet.
</Aside>

## Security

[Security overview](/guides/security/overview/) · [Firewall](/guides/security/firewall/) · [CrowdSec](/guides/security/crowdsec/) · [Malware](/guides/security/malware/) · [Countries](/guides/security/countries/) · [Your account](/guides/security/accounts/)

- **Overview** per server: firewall, CrowdSec, SSH root and password sign-in, pending and
  security updates, restart needed, and administrators without two-factor sign-in.
- **Firewall** (ufw): SSH, web and agent ports always stay open; open ports or block
  addresses from the server page. The panel refuses rules that would lock you out.
- **CrowdSec** in one click: SSH and WordPress password guessing, scans and exploit attempts
  are banned in the firewall, with bans, attacks and an allowlist in the panel.
- **Malware scans** with ClamAV, daily, weekly or on demand, with quarantine. Website owners
  see what was found on their sites.
- **Country blocking**: block some countries, or allow only some, using DB-IP's free country
  list.
- **Accounts**: two-factor sign-in (TOTP), sign-in rate limiting, "sign out all other
  devices", and an alert on sign-in from a new address.
- An append-only audit log of every change.

## Customers and packages

[Customers guide](/guides/admin/customers/)

- Packages with limits on websites, databases, apps, cron jobs, mail, disk space, memory and
  CPU, PHP versions, servers, allowed Docker images, Git apps, SFTP and FTP.
- Customers sign in to the same panel and see only what they own.
- Memory and CPU limits are enforced by the Linux kernel (cgroups) for all of a customer's
  PHP and containers. Disk use is measured every 30 minutes.
- "Sign in as" a customer for one hour, recorded in the audit log.
- <Badge text="next release" variant="note" /> [Move everything a customer has](/guides/admin/move-customer/)
  on one server to another in one go.

## Notifications

[Notifications guide](/guides/admin/notifications/)

- In the panel (a bell with an unread count) and by email, Telegram, Discord, Slack or signed
  webhooks.
- Events such as a server offline, a full disk, a failed backup, a website or app that fails
  to apply, a package near its disk limit, failed tasks and sign-in from a new address.
- Messages are written in each recipient's language.

## Many servers

[Servers guide](/guides/admin/servers/) · [Add a server](/start/add-server/) · [Updates](/guides/admin/updates/) · [Move a website](/guides/websites/move/) · [Move an app](/guides/apps/move/) · [Move a database](/guides/data/move-database/) · [Move a customer](/guides/admin/move-customer/) · [Rebuild from a backup](/guides/websites/rebuild/) · [Import from cPanel](/guides/admin/import-cpanel/)

- Add servers with one command, which installs the agent and the web server. The agent dials
  out to the panel over mutual TLS, so it works behind NAT.
- Signed releases and a one-line installer that checks the signature. The panel finds new
  releases, updates itself and then every server's agent from one page, keeps the previous
  version, and puts it back if the new one does not start. (The first release, v0.1.0, was
  published on 9 November 2026.)
- Live CPU, memory, disk, network, load and uptime, with 30 days of history.
- Services on each server (Caddy, PostgreSQL, cron and others) with restart.
- Background tasks with their progress shown in the panel.
- <Badge text="next release" variant="note" /> Moving a website, with the databases you choose,
  to another server: files (with owners and ACLs), databases and certificate are copied
  between the servers' agents, the new server is checked before anything switches, DNS the
  panel manages follows, and the old copy keeps serving until you remove it. Tested with two
  VMs.
- <Badge text="next release" variant="note" /> Moving an app to another server: the app is
  stopped, its Docker volumes (with numeric owners) and a Git app's current build are copied
  between the servers' agents, the new server sets it up and fills its volumes, DNS the panel
  manages follows, and the old copy stays stopped with its data until you remove it. Tested
  with two VMs.
- <Badge text="next release" variant="note" /> Moving a database on its own to another server,
  with the same user and password; the old copy stays until you remove it.
- <Badge text="next release" variant="note" /> Moving everything a customer has on one server
  (websites, databases and apps) in one go: all of it is checked first, then moved one thing
  after the other, stopping at the first failure.
- <Badge text="next release" variant="note" /> Rebuilding a website, with the databases you
  choose, on another server from its newest S3 backup when its server is gone. DNS the panel
  manages follows. Tested with two VMs and an S3 test server.
- <Badge text="next release" variant="note" /> Importing a cPanel account from its full backup
  (`cpmove` file): websites with their files, MySQL databases with the same names, users and
  passwords, and cron jobs, with a report of what was and was not imported. Email, DNS zones
  and certificates are not imported yet.

## API and command line

[REST API](/reference/api/) · [API tokens](/guides/security/api-tokens/) · [ekctl](/reference/cli/)

<Badge text="next release" variant="note" /> These are in the main repository's `dev` branch
and come with the release after v0.1.0.

- **API tokens** for scripts, for administrators and customers: scopes per area (read,
  websites, databases, apps, DNS, email, backups, servers, customers, settings), an expiry,
  shown once, revocable, last use shown, and named in the audit log. Tokens can never change
  account security or open a terminal.
- An **OpenAPI 3.1 description** of the whole API at `/api/v1/openapi.json`, with the scope
  each operation needs.
- **ekctl**, a command-line tool for Linux, macOS and Windows: servers, websites, databases,
  apps, DNS, backups and tasks, with `--wait`, `--json` output, and `ekctl api` for any
  endpoint. Panels with a self-signed certificate are trusted by fingerprint.

## Languages and interface

- English and বাংলা (Bangla), complete. Dates, numbers and sizes follow your language.
- Ready for right-to-left languages.
- Light and dark themes, a `Ctrl+K` command palette, and layouts that work on a phone.

## Not yet

These are planned for phase 4 of the [roadmap](/project/roadmap/). None of them works today.

| Area | What is planned |
| --- | --- |
| Terraform | A Terraform provider, with request and response schemas in the OpenAPI description |
| Importers | aaPanel, plain WordPress from another host, Coolify; from cPanel backups, also email, DNS zones and certificates |
| Resellers | Resellers with their own customers, white-label (name, logo, colours, domain), sub-users, passkeys, a list of active sessions |
| Security center | A web application firewall (Coraza with the OWASP Core Rule Set), rate limiting, fail2ban-style blocking for other services |
| Billing | Modules for WHMCS, Blesta and Paymenter; maybe built-in billing later |

Smaller things also still missing: a database browser and import/export, restoring a single
file or downloading a backup, suspending a customer, bandwidth limits, alerts for failed cron
jobs, wildcard certificates (DNS-01), and moving an item to another owner. Game servers come
after that, in phase 5.
